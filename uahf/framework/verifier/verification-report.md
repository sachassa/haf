## §0. 이 문서의 위치와 정본 경계

- **정본은 specs/06-verifier.md §3.2다.** 이 문서는 그 Core Contract의 **인스턴스**이며, 계약을 재정의·확장하지 않는다. 계약 요소는 § 포인터로만 참조한다(structure.md §7 C-1과 같은 인스턴스 원칙).
- 이 문서는 `framework/verifier/` 아래 **검증 리포트 스키마**를 확정한다. 06 §3.2-A(검증 리포트 6필드)·§3.2-B(항목별 판정 5필드·판정 값 3종)·§3.2-C(최종 판정 도출 규칙)의 계약을 이 경계 위에 배치·대조한다.
- **이 문서는 Module 구현 디렉터리 문서다.** `framework/verifier/`는 structure.md §2가 지정한 Module 구현 디렉터리 경계다(`framework/memory/`가 이 Module 구현 디렉터리 경계군의 첫 실사용 인스턴스였다 — structure.md §2 주). 이 문서 본문은 특정 AI 이름·모델명·제품 기능명·언어명·툴체인명·직렬화 형식명·물리 경로·확장자를 두지 않는다(structure.md §5 C-3 확장, 06 §3.3 INV-8).
- **물리 실현 비서술(경계).** 검증 리포트의 **물리 형식·직렬화·저장 위치·물리 경로**는 이 문서가 서술하지 않는다. 이는 **Adapter Binding 문서 소관**이다(06 §4 — §4.1 환경 바인딩·§4.2 이식 교체 지점; 물리 격리 경계는 `framework/adapters/<adapter>/`, structure.md §2·§6). 필요한 자리에는 일반형 표기 `<adapter>`와 소관 포인터만 둔다(§5).
- **인스턴스화 대상 경계.** 본 문서의 인스턴스화 대상은 위임 input이 지정한 06 §3.2-A/B/C 세 계약이다. 검증 유형 카탈로그(06 §3.2-E, VT-1~VT-5)·거짓 완료 보고 검출 계약(06 §3.2-F)·재작업 지시 포맷(06 §3.2-D)의 상세는 인스턴스화 대상이 아니며, 06 정본 § 포인터로만 참조한다(재정의·확장 0).
- **Verify 시점·전이 비정의(INV-9).** 이 문서는 검증 리포트 스키마만 인스턴스화한다. Verify 단계의 시점·전이·시퀀싱은 정의하지 않는다(06 INV-9, specs/03-loop.md 소관).
- **06 내부 § 포인터 표기 관례.** 06 정본 셀을 보존할 때, 06의 내부 § 포인터는 `06 §…` 접두로 명시하여 본 문서 자신의 절 번호와 구분한다. 이는 셀의 대상 지시를 명료화하는 표기이며 셀 내용(필드명·의미·필수/선택 표기)을 변경하지 않는다. 06의 명명 규칙 라벨(V1~V6, INV-1~INV-10, VT-1~VT-5)은 그대로 둔다.

## §2. 검증 리포트 스키마 인스턴스 (정본: 06 §3.2-A)

검증 리포트는 판정의 기록 산출물이다(ROADMAP v0.5 산출물 "검증 리포트 스키마"). 아래 필드·의미·필수 표기는 06 §3.2-A 정본을 **그대로 보존**한다(재정의 0, 새 필드 0). 필드명뿐 아니라 필수/선택(조건부) 속성 표기까지 정본과 일치시킨다.

| 필드 | 의미 | 필수 |
|---|---|---|
| `target` | 판정 대상 — 산출물 경로 목록과 대상 작업 식별자. | 예 |
| `criteria_basis` | 대조 기준 출처 — 무엇에 대조했는가(위임 완료 조건 / 규격 / 경계 규칙 / 시연 기준). | 예 |
| `items` | 항목별 판정 목록(06 §3.2-B). 최소 1건. | 예 |
| `final_verdict` | 최종 판정 — Pass / Fail / Conditional (06 §3.2-C). | 예 |
| `verifier_scope` | 이 검증이 실제로 검사한 범위. 검사하지 못했거나 제외한 범위를 함께 명시한다(V4). | 예 |
| `rework` | 재작업 지시(06 §3.2-D). `final_verdict`가 Fail 또는 Conditional일 때 필수, Pass면 "없음". | 조건부 |

- 항목별 판정의 스키마는 §3(정본 06 §3.2-B)이다.
- **표 말미 면책(파일당 1곳 — §2·§3·§4 공통 적용).** §2~§4의 표·규칙은 06 §3.2-A/B/C 정본을 인스턴스화할 뿐 계약을 재정의·확장하지 않는다. 필드·판정 값·도출 규칙의 상세 정본은 06 §3.2가 유지한다.

## §3. 항목별 판정 스키마 인스턴스 (정본: 06 §3.2-B)

항목별 판정은 대조 기준 1건에 대한 판정 단위다. `items`(§2)는 이 단위의 목록이다. 아래 필드·의미·필수 표기는 06 §3.2-B 정본을 **그대로 보존**한다(재정의 0, 새 필드 0).

| 필드 | 의미 | 필수 |
|---|---|---|
| `criterion` | 대조한 기준 1건. 검증 가능한 문장으로 표현한다. | 예 |
| `verdict` | 충족(Met) / 위반(Violated) / 판정 불가(Undetermined). | 예 |
| `evidence` | 판정 근거 — 산출물의 어느 부분이 근거인가(V3). | 예 |
| `scope` | 이 항목을 검사한 범위(V4). | 예 |
| `verification_type` | 이 항목에 적용한 검증 유형(06 §3.2-E, VT-1 ~ VT-5). | 예 |

**판정 값 정의 (06 §3.2-B, 재정의 0 — 새 판정 값 0):**

- **충족(Met)** — 기준이 산출물에서 만족됨을 근거로 확인했다.
- **위반(Violated)** — 기준이 산출물에서 만족되지 않음을 근거로 확인했다.
- **판정 불가(Undetermined)** — 근거 부족·검사 범위 한계로 충족/위반을 확정할 수 없다. 충족으로 취급하지 않는다(06 V6).

- 판정 값은 위 3종이 전부다(06 §3.2-B). 판정 불가를 충족으로 위장하지 않는다(06 V6, INV-3). 근거 없는 충족은 무효다(06 V3, INV-3).
- `verification_type`이 참조하는 검증 유형 카탈로그(VT-1 ~ VT-5)의 정본은 06 §3.2-E다(재서술 없음, § 포인터만 — §0).

## §4. 최종 판정 도출 규칙 인스턴스 (정본: 06 §3.2-C)

최종 판정(`final_verdict`, §2)은 항목별 판정 집합(`items`, §3)에서 **결정적으로** 도출된다(06 INV-5). 동일한 항목별 판정 집합은 항상 동일한 최종 판정을 낸다. 아래 규칙은 06 §3.2-C 정본을 그대로 보존한다(재정의 0).

- 모든 항목이 **충족(Met)** → **통과(Pass)**.
- 하나라도 **위반(Violated)** → **실패(Fail)**.
- 위반은 없으나 **판정 불가(Undetermined)**가 하나 이상 → **조건부(Conditional)**.

**조건부(Conditional)는 완료가 아니다**(06 §3.2-C). 판정 불가 항목이 해소되어 통과로 전이하거나, 그 항목이 완료를 막지 않는다는 Advisor의 최종 판정(재량)을 받아야 한다. 재량 판정은 Verifier가 하지 않는다(02 §3.2-A). 

- 도출은 결정적이다 — Verifier는 위반의 경중을 재량으로 감면하지 않는다(06 INV-5, §3.2-C).
- 최종 판정이 Pass가 아닌 산출물은 완료로 승인될 수 없다(06 INV-7 — 검증되지 않은 결과는 완료가 아니다).

## §5. 직렬화·저장 위치 경계 (Adapter Binding 소관 포인터)

- 검증 리포트의 **직렬화 형식·저장 위치·물리 경로**는 이 문서가 **일절 확정하지 않는다.** Core Contract(06 §3.2)는 추상 스키마이며, 직렬화 형식·저장 위치는 Adapter Binding이 정한다(06 §3.2 도입, §4).
- 이 물리 실현은 전부 **Adapter Binding 문서 소관**이며 `framework/adapters/<adapter>/` 뒤로 격리된다(06 §4.1 검증 리포트 직렬화 행·§4.2 이식 교체 지점 SP-2; structure.md §2·§6 Adapter 경계). 이식 시 §2~§4의 필수 필드·판정 값·도출 규칙·불변은 유지되고 물리 실현만 교체된다(06 §4.2, SP-2).
- 필요한 자리에는 일반형 표기 `<adapter>`와 "Adapter Binding 문서 소관" 포인터만 둔다. 검증 리포트가 실제로 어떤 형식으로 직렬화되고 어디에 저장되는가는 본 규격의 대상이 아니다.

## §6. v0.3·v0.4 실사용 리포트 필드 대응표 (실증)

**실증 = git 앵커 90ca19c.** v0.3·v0.4 검증 리포트 2건(각 CP2 독립 판정 산출물, Baseline 확정)이 §2 6필드·§3 5필드·§4 도출 규칙을 채운 확정 실사용 인스턴스이며, 도출 규칙의 **실패(Fail)·통과(Pass) 두 분기**와 `rework`의 조건부 전이(Fail 시 채움 → 재검증 Pass 후 "없음")를 실증한다. 스키마 요소 ↔ 두 리포트 절의 행 단위 대응표는 앵커 시점 본문이 보존한다.

- **조건부(Conditional) 분기는 이 두 실사용에 없다**(두 리포트 모두 판정 불가 0건). 조건부 도출·Advisor 재량 경계의 예시는 06 §8 예2가 담당한다 — 없는 케이스를 있다고 주장하지 않는다.

## §7. 경계와 비의존 (재정의 0 · 07 R2 · 금지 토큰 · Glossary)

본 문서가 준수하는 경계를 한자리에 모은다. 검증 대조 지점이다. 선언 1벌은 §0이며 본 절은 그 대조 항목만 열거한다.

- **06 계약 재정의·확장 0.** §2~§4의 필드·판정 값·도출 규칙은 06 §3.2의 인스턴스이며 § 포인터로만 참조한다. 스키마 표는 정본을 그대로 보존한다(새 필드·새 판정 값 0). 위반(형태 B가 06 §3 계약을 바꾸어야만 성립하는 경우)이 발견되면 구현하지 않고 Advisor에게 보고한다.
- **인스턴스화 대상 경계.** 위임 input(06 §3.2-A/B/C) 밖의 06 절(§3.2-D·§3.2-E·§3.2-F)은 재서술하지 않고 § 포인터로만 참조한다(§0).
- **Verify 시점·전이 비정의(INV-9).** Verify 단계의 시점·전이·시퀀싱은 정의하지 않는다(06 INV-9, 03-loop 소관). 본 문서는 검증 리포트 스키마만 소유한다.
- **직렬화·저장 위치 비서술.** 검증 리포트의 물리 형식·직렬화·저장 위치·물리 경로는 서술하지 않고 Adapter Binding 문서 소관 포인터로만 처리한다(§5).
- **금지 토큰·Glossary 경계.** 금지 토큰 규칙과 정당 매치 분류(정본 열거 어휘·Core Component 명칭·VT 라벨·저장소 문서 식별자)의 판정 기준은 framework/core/structure.md §5 C-3 확장이 소유한다(06 INV-8). 용어는 specs/00-glossary.md §3.2-J 정본만 사용하며 새 용어를 신설하지 않는다.
