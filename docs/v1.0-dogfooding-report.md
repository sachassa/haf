## §0. 이 문서의 위치·정본 경계·오케스트레이션 사실

### §0.1 위치·정본 경계

- **이 문서는 수행 기록이다.** Dogfooding 1건을 **실제로 어떻게 수행했고 무엇이 관측됐는가**를 실값으로 기록한다. **개발 사이클 내부의 독립 판정(CP2)**은 독립 Verifier(model: opus)가 수행했고, **본 기록 자체의 독립 검증(마일스톤 CP2)·최종 승인(CP3)**은 후속 소관이다 — 본 기록은 그 입력이며 스스로 최종 승인을 내지 않는다(02 §3.2-A). 상태 라인 "CP2 대기"는 후자를 가리킨다.
- **판정 문장은 12 §7 완료 기준·§3.2-C CK 항목·명세 §4 완료 기준의 인용 또는 예/아니오 환원이다.** 새 판정 기준·새 CK 항목·새 사유 코드·새 필드를 창설하지 않는다(재정의 0).
- **소유 경계 준수(07 R4).** 본 Task의 소유 경계는 3산출물 — (1) `dogfooding/uahf-lessons/` 이하(설치본 + CLI 구현 + Install Manifest + 사이클 내 검증 리포트) · (2) `docs/v1.0-dogfooding-report.md`(이 파일) · (3) `framework/adapters/claude/loop-data/v10-dogfooding.jsonl`(신규 1파일). 라이브 표면(라이브 `.claude/`·`framework/core`·`framework/runtime`·`framework/adapters` 바인딩·`specs/`)·기존 loop-data 10파일·기존 memory-data 62건·scaffold-template/ 원본은 **수정하지 않았다** — 읽거나(정독) 복사 원본으로만 참조했다(§7·§10 전수 대조).

### §0.2 오케스트레이션 사실 (수행 주체·역할 배치)

- **수행 주체.** Advisor(주 세션)가 Dogfooding 오케스트레이션(위임 수령 → Consult → Plan(단일 Task 채택) → Execute(Worker) → Verify(독립 Verifier CP2) → Learn → Memory Update → Complete, loop-protocol §3)을 주관했다. 설치 물리 배치·CK 재현·Bootstrap 판정·CLI 구현·실행 관측·loop-data 기록은 Worker Execute 산출이다.
- **실위임(모의 아님, L-07).** ④ 개발 사이클의 CP2는 **독립 Verifier 서브에이전트(`.claude/agents/verifier.md`, DP-E8 `model: opus`)에 실위임**했다 — CLI를 구현한 Execute 주체(Worker)와 검증 주체(Verifier)가 분리되어, 구현자가 자신의 산출물을 최종 판정하지 못함을 실증한다(13 §3.2-A 검증 게이트). Verifier가 CLI를 **직접 실행**해 명세 §4 케이스 a~e를 재관측하고 검증 리포트(`dogfooding/uahf-lessons/verify-uahf-lessons.md`)를 산출한 뒤에만 그 판정을 전이 이벤트 seq5·§6.4에 기록했다.
- **Advisor 조건부 사전 승인 문면(위임 시 제공).** "검증 final_verdict=Pass인 경우에만 '개발 사이클 승인 — 검증 Pass 확인'을 기록. Fail이면 승인 없이 재작업 또는 실패 보고." 최종 게이트는 본 Task 전체에 대한 Advisor 게이트 C·마일스톤 CP2가 수행한다.
- **actor=human 0건.** 사이클 7 line 전건 actor ∈ {Advisor, Worker, Verifier}, human 0건(§8 실측).
- **Memory Update 소관 구분(Advisor 결정 — 위임 constraint).** 사이클의 Learn 산출(성공 경로 BP 후보)은 본 기록에 **후보로 기재만** 하며, **물리 memory-data append는 후속 승격 심사 소관**이다. 본 수행은 memory-data에 append하지 않았고(기존 62건 무변경), loop-data seq6·7 `ref`는 `record:mi` 실 id를 주장하지 않는다(§8.2·L-07).
- **`at`·timestamp = 순서 값(L-09).** loop-data `at`(1..7)·Install Manifest `timestamp`(order:1)는 순서 값이며 물리 벽시계 시각 주장이 아니다(§8.3).

### §7.3 케이스 e — 읽기 전용 실증 (실행 전후 무변경, 실측)

a~c·보조 전 케이스 실행 전후로 `memory-data/` 전 트리(index 1 + store 61 = **62파일**) md5 스냅샷과 index.jsonl size·mtime을 대조했다:

- **md5 스냅샷: 62파일 전건 동일(변경 0)** — `diff`(before↔after) IDENTICAL.
- **index.jsonl: size=18621·mtime 무변경** — 실행 전후 동일.
- 결론: CLI 실행이 index.jsonl 및 store에 **쓰지 않는다**(byte·mtime 무변경). 62파일 전수 대조로 단일 파일 대리 지표에 의존하지 않았다(BP-01).

### §7.4 실행 관측이 드러낸 결함과 수정 (DI-INV-4 실증)

- **결함.** 초기 구현은 Windows 기본 콘솔 인코딩(cp949)에서 digest의 em-dash(—, U+2014) 등 비-cp949 문자 출력 시 `UnicodeEncodeError`로 표시 중 중단됐다(매칭 있는 전 케이스에서 재현). 정형 파일 대상임에도 **출력 인코딩**이 원인 — 필터·계수 로직과 무관.
- **재현 조건.** `python src/uahf_lessons.py <index>` 실행 시 첫 레코드(digest에 em-dash 포함) 출력에서 중단. `matched: N` 요약이 인쇄되지 못함.
- **수정.** 시작 시 표준 출력/오류를 UTF-8로 재설정(표준 라이브러리 `TextIOWrapper.reconfigure(encoding="utf-8")`, 실패 시 무해 통과). 수정 후 케이스 a~e·보조 전건 통과·한국어/em-dash 정상 표시(케이스 d stderr 메시지 정상 출력로 확인).
- **의의.** "실행 없는 구현 완료는 무효"(명세 §6·DI-INV-4)의 실증 — 정적 코드로는 통과처럼 보이나 실제 실행이 환경 의존 결함을 드러냈고, 관측→수정→재관측으로 완료를 성립시켰다. 이 결함·수정 경로는 Lesson 후보다(§완료 보고).

### §8.3 `at`·timestamp = 순서 값 (L-09)

- **loop-data `at`.** `v10-dogfooding.jsonl` `at`=1..7은 사이클 내 단조 증가 순서 값(seq와 동반)이며 **물리 벽시계 시각이 아니다**(loop-binding §3.3). 본 기록은 `at`을 "실제 수행 시각"으로 서술하지 않는다.
