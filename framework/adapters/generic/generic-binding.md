## §0. 이 문서의 위치와 정본 경계

- **정본은 Frozen specs/11-adapters.md §3(§3.2-A 바인딩 지점 목록·§3.2-B 최소 구현 Adapter·최소 바인딩 부분집합·§3.2-C 구조 규격·§3.3 Invariants)와 §4.2(2nd Adapter 배치)다.** 이 문서는 그 계약의 **환경 중립 실현 매핑**이며, 계약 요소(바인딩 지점 정의·필수/선택 지위·등급 기준·불변 규칙·Report 필드·verdict 값)를 **재정의·확장하지 않는다**. 계약 요소는 11 § 포인터로만 인용한다.
- 이 문서는 `framework/adapters/generic/` 소속 **Adapter Binding 문서**다. 11 §4.2가 두 번째 Adapter의 배치로 허용한 `adapters/generic/`의 실현 자리이며(ROADMAP v1.0; 11 §4.2는 특정 AI 벤더명을 포함한 다른 후보 경로도 병기하나, 그 경로는 본 문서 본문에서 명명하지 않는다 — DP-V6), 최소 구현 Adapter의 **최소 바인딩 부분집합(BP-1~5, BP-7~11, BP-13~15 = 필수 13개)**만 대상 환경 값(여기서는 환경 중립 값)으로 실현하고 선택 바인딩(BP-6·12·16·17)은 생략한다(11 §3.2-B·§4.2, §3).
- **DP-V6 정체성 제약 — 격리 지점이되 환경 중립.** 일반적으로 Adapter 경계는 **격리 지점**이어서, Core 문서 본문의 AI·언어·툴체인 비의존 규칙(structure.md §5 C-3)이 **비적용**이며 구체 환경 토큰이 허용된다(첫 번째 Adapter의 자매 바인딩 문서 §0과 동형). 그러나 **Generic Adapter는 다르다** — DP-V6(§4)에 따라 본 문서는 특정 AI 이름·모델명·AI 벤더 제품/기능명을 본문에 **0건**으로 유지한다. 이는 C-3 의무(그건 Core 경계 대상이다)가 아니라 **generic Adapter의 정체성 제약**이다. Generic은 진정 환경 중립·추상이되 **실행 가능한 실현**으로 각 바인딩 지점을 실현한다 — 예: "일반 텍스트 파일 기반 채널", "일반 실행 세션", "파일 시스템 디렉터리 규약". (개방 표준 포맷명·"파일"·"디렉터리"·"텍스트" 등 중립 메커니즘 표기는 허용된다. UAHF 자신의 계약 용어 — Advisor/Planner/Worker/Verifier·Module·Manifest·Config·Bootstrap/Serve/Shutdown·Agent 등 — 은 Glossary 정본 AI 비의존 용어이므로 제약 대상이 아니다.)
- **창설 금지.** 이 문서는 11 §3.2-A **17개 바인딩 지점을 넘어서는 새 바인딩 지점(새 BP)을 창설하지 않는다.** 11 §3.2-D 6필드를 넘어서는 **새 Report 필드**를, 11 §3.2-B의 `Valid(Full)`/`Valid(Minimal)`/`Invalid`를 넘어서는 **새 verdict 값**을 만들지 않는다. 바인딩 지점·필수/선택 지위·Conformance 기준·등급 정의는 전부 11 §3이 소유하며, 본 문서는 최소 부분집합의 환경 중립 바인딩 값만 확정한다.
- **판정 미산출(선취 금지).** 본 문서는 **Conformance 판정(verdict)을 내지 않는다.** C1~C3 대조·Conformance Report(11 §3.2-D) 산출·Valid(Minimal) 판정은 **후속 Task 소관**이며, 본 문서는 그 판정을 선취하지 않는다. 본 문서의 책임은 최소 바인딩 부분집합(필수 13개)의 환경 중립 값 확정과 선택 4개 생략의 명문화에 한정된다. (첫 번째 Adapter의 Conformance 판정 문서가 verdict를 산출하는 것과 달리, 본 문서는 그 자리를 채우지 않는다 — 본 문서는 바인딩 값 확정 문서이지 판정 문서가 아니다.)
- **하네스 상태·실현 형태.** 이 하네스는 현재 Bootstrap 상태다(Glossary J-13, delegation-protocol.md §0). Generic Adapter의 최소 바인딩은 정식 실행 Module이 아니라 **환경 중립 규약으로 확정된 값(형태 A)**이며, 그 값을 소비하는 **핵심 루프 실동작 시연**(위임→구현→검증→승인 1회 통과)은 DP-V5의 실동작 사이클로 후속 Task(시연 문서)가 실증한다. `형태 A`(문서·규약)·`형태 B`(실행 코드)는 Glossary §3.2-G 서술 라벨이다.
- **실측 기반 상태 서술(L-07).** "실재/존재/미존재" 주장은 파일 시스템 확인 후에만 기입한다(session-handoff-v0.3 §1.4 A5 사례·Active Lesson L-07). §2 "실재 여부" 열·§5 실측 대조 표의 전 행은 파일 시스템 직접 실측에 근거하며, **미존재를 실재로, 미래 시연 산출물을 현재 실재로 쓰지 않는다.**
- 용어는 specs/00-glossary.md 정본만 사용한다. Adapter Interface·바인딩 지점(Binding Point)·Conformance·완전/최소 구현 Adapter·핵심 루프(Core Loop)는 Glossary §3.2 정본이며(11 §9 OQ-2 승격), 본 문서는 그 최소 부분집합의 환경 중립 값만 확정한다. `DP-V1`·`DP-V5`·`DP-V6`는 본 문서가 기록하는 Advisor 결정 라벨이다(§4). 새 용어 신설 0.

## §1. 목적

이 문서는 Frozen specs/11의 Adapter Interface(§3.2-A) 중 **최소 구현 Adapter의 최소 바인딩 부분집합(필수 13개)**을 **Generic Adapter**의 환경 중립 바인딩 값으로 확정한다(11 §3.2-B·§4.2, ROADMAP v1.0).

책임은 네 가지다.

- 11 §3.2-B 최소 바인딩 부분집합 **필수 13개(BP-1·2·3·4·5·7·8·9·10·11·13·14·15)** 각각에 대해, 무엇을 바인딩하는가(11 §3.2-A 정본 인용)·generic 환경 중립 바인딩 값·실재 여부를 하나의 매핑 표로 확정한다(§2, done 1) — 13행 전건, 누락 0.
- 선택 바인딩 4개(BP-6·12·16·17)의 **생략**을 11 §3.2-B 인용과 함께 명문화한다(§3, done 2).
- Advisor 결정 3건(DP-V1·DP-V5·DP-V6)을 기록한다(§4, done 5) — Worker는 **기록만** 하며 결정 주체는 Advisor다(사용자 승인 2026-07-06 계획). 그리고 상태 서술을 실측과 대조한다(§5, done 6).
- 본문에 특정 AI 이름·모델명·AI 벤더 제품/기능명이 0건임을 유지한다(DP-V6, §0·§6, done 3).

이 문서는 11 §3의 어떤 계약 요소도 재정의·확장하지 않으며(§0·§6, done 4), **Conformance verdict를 산출하지 않는다**(선취 금지 — 판정은 후속 Task 소관).

## §2. 최소 바인딩 부분집합 — 필수 13 BP 환경 중립 바인딩 값 (done 1)

11 §3.2-B 최소 바인딩 부분집합의 **필수 13개** 각각을 Generic Adapter의 환경 중립 값으로 확정한다. "무엇을 바인딩하는가" 열은 11 §3.2-A 정본 표의 값을 **그대로 인용**하고, "generic 환경 중립 바인딩 값" 열이 그 지점을 특정 AI·벤더 제품에 종속되지 않는 일반 메커니즘(파일·디렉터리·텍스트·실행 세션·실행 주체)으로 실현하며, "실재 여부" 열이 규약 확정(환경 중립 값이 본 문서에서 확정됨)과 시연 예정(DP-V5 실동작 사이클로 후속 Task가 실증)을 정직하게 구분한다(§5 실측 대조).

| BP | 무엇을 바인딩하는가 (11 §3.2-A 정본 인용) | generic 환경 중립 바인딩 값 | 실재 여부 |
|---|---|---|---|
| BP-1 | Module/Plugin Manifest를 대상 환경의 서술자 포맷으로 직렬화 | 서술자 필드를 담는 **일반 구조화 텍스트 파일**(머리말 메타데이터 블록 + 본문). 대상 환경의 서술자 포맷은 개방 표준 구조화 텍스트 직렬화 형식으로 실현하며, 특정 직렬화 제품·형식을 강제하지 않는다. | 규약 확정 — 환경 중립 직렬화 규약 확정. 서술자 파일 실물·완전 인스턴스는 시연 예정(DP-V5, 후속 Task) |
| BP-2 | Module 정의를 로드해 entrypoint를 해소하는 로더 | 파일 시스템 경로 규약에 따라 대상 계약(역할)의 **활성 정의 파일을 읽어 entrypoint(활성 정의)를 해소**하는 로드 절차. 위임 착수 시 해당 역할의 정의 파일을 조회·로드한다(계약당 활성 정의 1개). | 규약 확정 — 파일 기반 로드 절차 규약 확정. 실행 로더는 형태 B(시연 예정) |

- **환경 중립성(DP-V6).** generic 값 열의 모든 표현은 일반 메커니즘(파일·디렉터리·텍스트·실행 세션·실행 주체·레코드)과 UAHF 자신의 계약 용어(Glossary 정본)로만 서술했다. 특정 AI 이름·모델명·AI 벤더 제품/기능명은 0건이다(§6 자가 전수 스캔).

- **핵심 루프 소비 표면(DP-V5).** DP-V5가 실동작 사이클의 소비 바인딩 표면으로 지정한 4종 — 파일 기반 위임 메시지(BP-10)·보고 파일(BP-11)·기록 파일(BP-13)·문서 역할 정의(BP-7) — 이 위 표에 그대로 대응한다. 실동작 수행 시 물리 수행 주체가 무엇인지의 투명 기재는 **시연 문서(후속 Task) 소관**이며, 본 문서는 환경 중립 값만 확정한다(DP-V6, §4).

## §3. 선택 바인딩 생략 (done 2 — BP-6·12·16·17)

11 §3.2-B **최소 구현 Adapter(Minimal Adapter)** 정의를 인용한다:

> "최소 구현 Adapter (Minimal Adapter) — C1~C3을 만족하되, 각 필수 바인딩의 내용은 핵심 루프 1회 통과에 필요한 최소 수준이면 된다. **선택 바인딩(BP-6, BP-12, BP-16, BP-17)은 생략할 수 있다.**" (11 §3.2-B)

또한 11 §4.2:

> "최소 구현 Adapter는 §3.2-B의 최소 바인딩 부분집합(BP-1~5, BP-7~11, BP-13~15)만 대상 환경 값으로 교체하고, **선택 바인딩(BP-6·BP-12·BP-16·BP-17)은 생략할 수 있다.**" (11 §4.2)

이에 따라 Generic Adapter(최소 구현 Adapter)는 아래 선택 바인딩 4개를 **생략한다.**

| BP (선택) | 무엇을 바인딩하는가 (11 §3.2-A 정본 인용) | 생략 |
|---|---|---|
| BP-6 | 확장 Module(확장점·능력·묶음)의 등록·발견·지연 로드·배포 표면 | 생략 (11 §3.2-B·§4.2 — 최소 구현 Adapter는 선택 바인딩 생략 가능) |
| BP-12 | Memory Service 영속성 백엔드 (단일 Port 뒤) | 생략 (동상) |
| BP-16 | 이벤트 원천의 계측·방출 지점과 확장 실행기(결정적 순서·격리)·원천 컨텍스트 전달 | 생략 (동상) |
| BP-17 | 상황 서술자와 적용 조건의 대조 알고리즘 | 생략 (동상) |

주:

- 위 생략은 11 §3.2-B **최소 구현 Adapter 정의가 명시적으로 허용**한 것이며, 필수 완전성(11 §3.1 C1·INV-2)을 침해하지 않는다 — C1은 **필수** 바인딩(§3.2-A에서 mandatory로 표시된 지점)의 완전성만 요구하고, BP-6·12·16·17은 §3.2-A·§3.2-B가 **선택(optional)**으로 지정한 지점이다.
- 목적은 Adapter Interface가 다른 실행 환경에 적용 가능함을 증명하는 것이지 기능 완성이 아니다(11 §3.2-B·ROADMAP v1.0). 선택 바인딩 생략은 이 목적과 정렬한다.
- 본 문서는 생략을 **명문화**할 뿐, 그 생략이 최종 등급(Valid(Minimal))에 이르는지의 **판정(verdict)은 내지 않는다** — 판정은 후속 Task 소관이다(§0 판정 미산출, 선취 금지).

## §4. Advisor 결정 기록 (done 5 — DP-V1·DP-V5·DP-V6)

아래 세 결정의 **주체는 Advisor**이며(사용자 승인 2026-07-06 계획), 본 문서는 그 결정을 **기록만** 한다 — Worker는 Architecture·설계 결정을 하지 않는다(02 §3.2-A·INV-3; Architecture·설계 결정은 Advisor 소관). 세 결정은 Frozen specs/11을 **무변경**으로 유지한다.

### DP-V1 — 2nd Adapter = Generic, 배치 `framework/adapters/generic/`

- **결정.** 두 번째 Adapter는 **Generic Adapter**로 하고, 배치 경로는 `framework/adapters/generic/`로 한다. 이는 11 §4.2가 두 번째 Adapter의 배치로 허용한 `adapters/generic/`의 채택이다(11 §4.2는 특정 AI 벤더명을 포함한 다른 후보 경로도 병기하나, 그 경로는 본 문서 본문에서 명명하지 않는다 — DP-V6).
- **물리 경로 해소.** 11 §3.2-C·§4.2의 `adapters/generic/` 표기는 물리 경로 `framework/adapters/generic/`의 축약으로 해소한다(물리 정본 = structure.md §2 Adapter 경계 일반형 `framework/adapters/<adapter>/`의 `<adapter>` = `generic` 구체화). 이는 첫 번째 Adapter가 자신의 배치 표기를 물리 경로로 해소한 동형 결정(그 Adapter의 Conformance 판정 문서 §5 DP-A2)과 같은 방식이다.
- **Frozen 11 무변경.** 이 결정은 Frozen specs/11 문면을 수정하지 않는다 — 11이 이미 제시한 선택지의 채택이자 표기의 물리 경로 해소일 뿐이다.

### DP-V5 — C3(핵심 루프 통과) 실증 방식 = 실동작 사이클

- **결정.** C3(핵심 루프 통과, 11 §3.1) 실증은 **실동작 사이클**로 한다 — 핵심 루프 4단계(위임→구현→검증→승인)를 실제 수행하되, **소비 바인딩 표면은 전부 generic 바인딩 값**(파일 기반 위임 메시지[BP-10]·보고 파일[BP-11]·기록 파일[BP-13]·문서 역할 정의[BP-7])으로 한다.
- **BP-9 값 명문.** BP-9(실행 모델·엔진 지정)의 generic 값 = **"임의 실행 주체(any executor) — 역할 정의 문서를 준수하는 어떤 실행 주체든 가능"**(§2 BP-9 행에 반영).
- **투명 기재의 소관.** 실동작 시 물리 수행 주체가 무엇인지의 투명 기재는 **시연 문서(후속 Task) 소관**이다. 본 문서(generic-binding.md)는 환경 중립 바인딩 값만 확정하며, 물리 수행 주체를 명명하지 않는다(DP-V6).
- **본 문서 범위.** 본 문서는 실동작 사이클을 **수행·판정하지 않는다** — 소비될 환경 중립 바인딩 값의 확정에 한정한다. 실동작 통과·C3 판정은 후속 Task 소관이다(§0 판정 미산출).

### DP-V6 — Generic 정체성 = 진정 환경 중립·추상이되 실행 가능한 실현

- **결정.** Generic Adapter의 정체성은 **진정 환경 중립·추상이되 실행 가능한 실현**이다 — 예: "일반 텍스트 파일 기반 채널", "일반 실행 세션", "파일 시스템 디렉터리 규약". 본문에 특정 AI 이름·모델명·AI 벤더 제품/기능명을 **0건**으로 유지한다.
- **제약의 성격.** 이 0건 제약은 **C-3 의무가 아니라 generic Adapter의 정체성 제약**이다 — structure.md §5 C-3은 Core 경계(`framework/core/`·`framework/runtime/`)·Module 구현 디렉터리 문서 본문에 적용되는 규칙이고, Adapter 경계는 일반적으로 격리 지점으로 C-3 비적용이다(첫 번째 Adapter의 자매 바인딩 문서는 구체 토큰을 허용). Generic Adapter만은 자신의 정체성상 이 제약을 **별도로** 진다. 본 결정에 따라 §0에 정체성 제약으로 명문화했다.
- **허용 표기.** 개방 표준 포맷명·"파일"·"디렉터리"·"텍스트" 등 중립 메커니즘 표기와 UAHF 자신의 계약 용어(Glossary 정본)는 제약 대상이 아니다(§0·§6).

주: 세 결정 모두 Advisor 소관(02 §3.2-A·INV-3)이며, 본 문서는 결정의 실재와 정본 정합(재정의 0)을 기록한다. 결정의 재평가·창설은 수행하지 않는다.

## §6. 정본 경계·격리·계약 소유 (self-note)

- **재정의·확장 0 (done 4).** 본 문서의 모든 서술은 11 §3(Adapter Interface·Conformance·구조 규격·불변 규칙)의 **환경 중립 실현 매핑**이다. 어떤 바인딩 지점 정의·필수/선택 지위·판정 조건(C1~C3)·Report 필드·verdict 값·등급 기준·불변 규칙도 이 문서에서 새로 확정되지 않는다 — 정본은 11 §3이다. **11 §3.2-A 17개 목록을 넘어서는 새 바인딩 지점·11 §3.2-D 6필드를 넘어서는 새 Report 필드·11 §3.2-B 3종 verdict를 넘어서는 새 verdict 값·새 등급·새 용어를 창설하지 않았다.**
- **판정 미산출(선취 금지, done 4).** 본 문서는 **Conformance verdict(Valid(Minimal) 등)를 산출하지 않는다.** C1~C3 대조·Conformance Report 산출·최종 판정은 후속 Task 소관이며, 본 문서는 그 자리를 선취하지 않는다. 본 문서의 책임은 최소 바인딩 부분집합(필수 13개)의 환경 중립 값 확정과 선택 4개 생략 명문화뿐이다.
- **DP-V6 정체성 제약 준수 (done 3).** 본문에 특정 AI 이름·모델명·AI 벤더 제품/기능명을 **0건**으로 유지했다. generic 값은 일반 메커니즘(파일·디렉터리·텍스트·실행 세션·실행 주체·레코드)과 UAHF 자신의 Glossary 정본 계약 용어로만 서술했다. **자가 전수 스캔**을 후보 집합 전체(AI 이름·모델명·AI 벤더 제품명·제품 기능 표면명 — 특정 대화형 AI 제품명·특정 모델 계열명·특정 CLI/에이전트 제품명·특정 하위 실행 단위 기능명·특정 설정 디렉터리 제품 표기 등)로 수행했으며, 단일 토큰 검색 하나로 넓은 결론을 내지 않았다(§ verify_basis에 스캔 범위·후보 집합 명시). 개방 표준 포맷명·중립 메커니즘 표기는 허용 범위다(DP-V6·§0).
- **Frozen 무변경.** specs/11(Frozen v0.1)을 수정하지 않았다. DP-V1·DP-V5·DP-V6(§4)은 Frozen 문면의 선택지 채택·실증 방식·정체성 제약을 기록하는 Advisor 결정이며 Frozen 문면 자체를 바꾸지 않는다.

- **동시 작성 문서 불인용 (07 R2).** 동시 작성 중인 형제 Task 산출물(docs/v1.0-dogfooding-spec.md·scaffold-binding.md 개정분)을 인용·추측하지 않았다. 참조한 확정 정본은 Frozen specs(11·00)·framework/core/structure.md·첫 번째 Adapter의 Baseline 자매 바인딩 문서(구조 관례 표본으로만)·AGENT.md(상위 규약)·docs/delegation-protocol.md뿐이다. 자매 바인딩 문서의 **바인딩 값 내용은 복제하지 않았다** — generic은 자신의 환경 중립 값을 확정한다.
