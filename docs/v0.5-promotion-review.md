## §1. 심사 기준 (05 §3.2-A 승격 3조건 — 재정의 없이 적용)

1. `failure`(BP는 `success`)·`cause`(BP 제외)·`lesson`(BP는 `practice`)·`applicability`·`provenance`가 모두 채워질 수 있다 (검증 가능성, 05 INV-5).
2. Verifier의 Learn 입력(독립 판정) 또는 실검출·재작업·교정의 실물 기록이 실패(성공)의 실재를 뒷받침한다.
3. Advisor가 승격을 승인한다 — **본 문서의 각 판정이 그 승인이다.**

등록(V10-(ii))에서의 성립 방식: Register Candidate → 본 문서 §2·§3 해당 행 참조 첨부 → Active 승격. 본 문서 참조 없는 승격 시도는 NotApproved다 (05 INV-4). 등록은 §2~§4의 확정 필드값 그대로 수행한다 (추측·개작 금지). labels 투영은 framework/memory/lessons.md §5.2 규칙(적용 조건·안정 id·status·재발 레코드 verdict·matched_lesson_id → labels)에 따라 V10-(ii)가 수행하되 applicability 문장과 정합해야 한다.

## §2. Lesson 후보 심사 (3건 — 전건 승인)

### L-09 [승인] 기록 내 timestamp 성격 구분 서술 (v0.4 이월 후보 1)
- failure: v0.4 시연 기록(demo.md)이 생성기 배정 순서 값인 기록 timestamp를 "실제 수행 시각"으로 서술했고, 실측상 물리 파일은 25ms 창 일괄 생성이어서 서술↔실측 모순으로 CP2 Fail이 났다 (r3 서술 교정으로 해소).
- cause: 시각 주장을 실측 대조 없이 기입했고, 기록 필드의 timestamp(순서 값)와 물리 생성 시각(실측)의 성격을 구분하지 않았다.
- lesson: 기록 필드의 timestamp(순서 값)와 물리 생성 시각(실측)을 구분 서술한다. "실제 수행 시각" 류 주장은 실측 대조 후에만 기입하고, 시각 주장을 넣지 않으면 넣지 않았음을 명시한다.
- applicability: 시연·수행 기록에 timestamp·시각 주장을 서술하는 상황.
- provenance: task_ref=v0.4 M7/M8·demo.md r3 / report_ref=docs/v0.4-verification-report.md §3.6·item #31, docs/session-handoff-v0.4.md §1.5-1 / origin_role=검출 Verifier(v0.4)·승인 Advisor(v0.5) / ordering_ref=v0.4 세션 발생·v0.5 세션 등록.
- 조건 2 근거: v0.4 검증 리포트 최초 Fail(item #31)→r3 재작업→Pass의 실물 기록. v0.5에서 V7 §3 기록 요건 2·V8 준수로 재발 방지가 실사용됨 (v0.5 CP2 Pass).

### L-10 [승인] 재검증 기준의 적용 범위 명시 (v0.4 이월 후보 2)
- failure: v0.4 개정(memory-binding r2)이 재작업 지시의 "잔존 서술 0건" 기준을 이력 행(시점 기록)에 과잉 적용해 r1 이력 행 문면을 교정했고, r3에서 원복해야 했다.
- cause: 재작업 지시의 전칭 기준("잔존 0건")이 적용되는 범위(라이브 본문)와 제외 범위(시점-스코프 기록)를 명시하지 않았다.
- lesson: 재작업 지시의 "잔존 서술 0건" 류 기준은 라이브 본문에 적용됨을 명시하고, 시점-스코프 기록(이력 행·인용·교정 경위)은 적용 대상에서 제외 명시한다. 이력 행 문면은 append-only 불변이다.
- applicability: 재작업 지시·재검증 기준을 작성하거나 적용하는 상황.
- provenance: task_ref=v0.4 M5 r2→r3 / report_ref=docs/session-handoff-v0.4.md §1.3(이력 행 시점 기록 원칙 — Advisor 판정)·§1.5-2 / origin_role=판정 Advisor(v0.4)·승인 Advisor(v0.5) / ordering_ref=v0.4 세션 발생·v0.5 세션 등록.
- 조건 2 근거: v0.4 r2→r3 원복의 실물 이력. v0.5에서 규격으로 편입(framework/verifier/rework-instruction.md §4)되어 V9 CP2 판정에 실적용됨.

### L-11 [승인] 위임문 경계 문안 사전 대조 (v0.5 신규)
- failure: v0.5 위임(V12)의 done 문구가 특정 Adapter Binding 문서명 포인터를 산출물 본문 문안으로 지정해, Module 구현 디렉터리 문서 본문에 이식 불변(04 §4.2·C-1 — Adapter만 교체·Core/Module 무변경)을 깨는 환경 결합이 유입되었다. Worker는 지시를 이행하며 소지를 투명 보고했고, Advisor 게이트 C가 검출해 r4로 교정했다.
- cause: 위임 메시지가 산출물 본문에 들어갈 문안을 지정하면서, 그 문안 자체를 대상 경계의 금지·격리 규칙으로 사전 대조하지 않았다.
- lesson: 위임 메시지가 산출물 본문 문안을 지정할 때 그 문안 자체를 대상 경계의 금지·격리 규칙으로 사전 대조한다 — 위임문도 경계 검증 대상이다.
- applicability: 위임 메시지에 산출물 본문 문안·포인터 표기를 지정하는 상황.
- provenance: task_ref=v0.5 V12 r3→r4 / report_ref=본 세션 게이트 기록(V12 r4 지시 — Advisor 소관 결함 명시), framework/memory/lessons.md §9 r4 행 / origin_role=결함 Advisor(v0.5)·인지 보고 Worker(v0.5)·검출·승인 Advisor(v0.5) / ordering_ref=v0.5 세션.
- 조건 2 근거: lessons.md §9 r4 행(교정 사유 — Advisor 위임문 문안 교정)·r4 후 잔존 0건의 V9 CP2 독립 실측 확인.

## §4. 재발 판정 레코드 입력 확정 (1건 — Judge Recurrence)

v0.4 timestamp 실패(§2 L-09의 failure)에 대한 재발 판정이다. 판정 연산의 입력(작업별 회수 이력)은 03 미구현 동안 수동 제공한다 (lessons.md §4, handoff §3.4-3).

- failure_signature: 시연·수행 기록이 기록 필드의 timestamp(생성기 배정 순서 값)를 "실제 수행 시각"으로 서술 — 상태·시각 주장을 실측 대조 없이 기입한 서술↔실측 모순 (L-07 동종 부류).
- matched_lesson_id: **L-07** (상태 서술 실측 후 기록 — Active, v0.4 승격).
- was_recalled: **true** — 수동 제공 회수 이력: v0.4 세션에서 L-07이 회수·적용되었음이 handoff §1.5-1에 명시된다 ("L-07이 이 세션에 회수·적용되었음에도 동종 실패 발생").
- verdict: **Recurrence** (매칭 Active Lesson 존재 + 회수 집합 포함 — lessons.md §4 진리표).
- follow_up: 보다 특정한 Lesson(L-09 — timestamp 성격 구분)을 등록·승격한다 (본 문서 §2 L-09). v0.5부터 절차 요건화(v0.5-demo-procedure §3 요건 2)로 재발 방지를 규격에 내장했다.

## §5. 판정 요약 · 등록 지시 (V10-(ii) 위임 input)

- Lesson 후보 3건 전건 **승격 승인** (L-09·L-10·L-11). BP 후보 1건 **승격 승인** (BP-02), 1건 **보류** (등록하지 않음 — §3 보류 근거). 재발 판정 레코드 1건 입력 확정 (§4).
