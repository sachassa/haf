## §0. 이 문서의 위치와 정본 경계

이 절이 본 문서의 경계 선언 정본이다(다른 절에서 반복하지 않는다).

- **정본은 specs/03-loop.md §3.2다.** 이 문서는 그 Core Contract의 **인스턴스**이며 재정의·확장하지 않는다(structure.md §7 C-1). 위반이 발견되면 구현하지 않고 Advisor에게 보고한다.
- **Module 구현 디렉터리 문서.** `framework/loop/`는 structure.md §2가 지정한 경계이며, 이 문서가 그 경계의 첫 실사용 인스턴스다(structure.md §8 트리 — loop는 종전 빈 디렉터리). 본문 전체에 금지 토큰(AI 이름·모델명·제품 기능명·언어명·툴체인명·직렬화 형식명·물리 경로·확장자)을 두지 않는다 — 규칙·분류 정본은 structure.md §5 C-3(및 03 §3.3 INV-9)이다. 작성 시점의 동시 작성 형제 불인용(07 R2)·추측 0(07 R4) 준수 서술 = 종전 문면 git 앵커 90ca19c(정본 = uahf/specs/07-workflow.md §3.2-C).
- **물리 실현 비서술.** 루프 상태 기록의 물리 형식·직렬화·저장 위치·물리 경로는 서술하지 않는다 — Adapter Binding 소관이다(03 §4.1·§4.2 SP-3; 격리 경계 `framework/adapters/<adapter>/`, structure.md §2·§6). 상세는 §7.

## §2. 전이 이벤트 스키마 인스턴스

정본 = `uahf/specs/03-loop.md §3.2-A`(재정의 0 · 문면은 정본 참조). 루프 상태 기록은 전이 이벤트(Transition Event)의 순서 있는 append-only 로그이며, 전이 이벤트는 단계 전이 하나의 기록 단위다.

| 필드 | 의미 | 필수 |
|---|---|---|
| `cycle_id` | 이 Lifecycle 사이클의 식별자. 하나의 위임 = 하나의 사이클. | 예 |
| `seq` | 사이클 내 전이 순번. 단조 증가한다. | 예 |
| `from_stage` | 전이 이전 단계. 사이클 시작 시 없음. | 아니오 |
| `to_stage` | 전이 이후 단계. | 예 |
| `trigger` | 전이 사유 — 완료 조건 충족 / Verify 실패 / 재작업 되돌림 / 에스컬레이션. | 예 |
| `outcome` | 단계 결과 — pass / fail / escalated. | 예 |
| `retry_count` | 현재까지 재작업 되돌림 횟수 (03 §3.1-B). | 예 |
| `actor` | 전이를 유발한 역할 (Advisor/Planner/Worker/Verifier) 또는 human(사람 개입 시). | 예 |
| `ref` | 관련 산출물·보고 참조 (위임/완료/실패 보고, Verifier 판정 참조). | 아니오 |
| `at` | 전이 시점. 순서 보장용 추상 시각. | 예 |

- 필수 표기는 10필드 중 8필드가 **예**, `from_stage`·`ref`가 **아니오**다. `from_stage`는 사이클 첫 전이에 없고, `ref`는 관련 산출물이 없는 전이에서 생략될 수 있다(Consult 전이의 회수 집합 참조는 §6).
- `seq`(단조 증가)와 `at`(순서 보장용 추상 시각)이 전이의 순서를 확정한다. `at`의 물리 시각 표현은 Adapter Binding 소관이다(§7).
- 열거 값(`outcome` 3종·`trigger` 4종·`actor` 값)은 03 §3.2-A 정본이며 재정의·추가하지 않는다.

## §3. 단계 상태 인스턴스

정본 = `uahf/specs/03-loop.md §3.2-B`(재정의 0 · 새 상태 0). 각 단계는 다음 5종 상태 중 하나를 가진다.

- `Pending` — 진입 전.
- `Active` — 진입 후 진행 중.
- `Passed` — 완료 조건 충족. 다음 단계로 전이 가능.
- `Failed` — 완료 조건 불충족. 재작업 루프 대상.
- `Escalated` — 사람 개입 또는 상위 에스컬레이션 대상.

**읽기 보조 관찰(비계약).** 종료 상태 3종은 전이 이벤트 `outcome` 값(pass/fail/escalated, §2)과 어휘를 공유한다 — 한 단계의 결과가 그 단계에서 나가는 전이의 `outcome`에 기록된다. `Pending`/`Active`는 전이가 아직 기록되지 않은 단계 상태다. 새 계약이 아니다.

## §4. Learn 트리거 인스턴스

정본 = `uahf/specs/03-loop.md §3.2-C`(재정의 0 · 산출 후보 2종·트리거 규칙의 문면은 정본 참조). 실패 경로는 Lesson 후보(누적 실패 집합·실패 보고의 `lesson_candidate` 근거), 성공 경로는 Best Practice 후보를 도출하며, 성공이든 에스컬레이션이든 사이클 종료 전 Learn은 항상 실행된다(03 INV-5).

**본 문서 고유 델타 — 루프 상태 기록 측 사상.** 재작업 되돌림 하나는 하나의 전이 이벤트(`outcome` = fail, `retry_count` 증가)로 §2 스키마에 남고, Learn 단계의 진입·완료도 전이 이벤트(`to_stage` = Learn, 이어 `to_stage` = Memory Update)로 남는다.

**경계.** Learn은 도출만 한다. 후보의 포맷·생성 규칙·승격은 04/05 소관이며, 실제 기록은 Memory Update에서 Memory Service Interface(단일 Port) 경유로 이뤄진다(03 §5·INV-7). 본 문서는 후보의 내부 포맷을 인용·추측하지 않는다.

## §5. append-only 불변·사이클 재구성 포맷 규칙 (정본: 03 §3.2-A 불변 규칙·INV-3·§7)

- **append-only(INV-3).** 루프 상태 기록은 append-only다. 전이는 기록된 뒤에 유효하다. 기록되지 않은 전이는 없다. 기존 전이 이벤트는 정정·삭제하지 않으며, 갱신·정정이 필요하면 **새 전이 이벤트를 추가**한다.
- **전이 누락 금지(INV-3).** 모든 단계 전이는 정확히 하나의 전이 이벤트로 append된다 — 성공 경로 선형 전이(03 INV-1), 재작업 되돌림(03 §3.1-B), 에스컬레이션(`outcome` = escalated) 모두가 대상이다.
- **순서 확정.** `seq` 단조 증가와 `at` 추상 시각(§2)이 순서를 확정하고, 그 순서로 사이클의 단계 경로가 재현된다.
- **재구성 가능 요건(03 §7).** 이 로그만으로 사이클 전체를 재구성·검증할 수 있어야 한다 — 각 이벤트의 `from_stage`·`to_stage`·`trigger`·`outcome`·`retry_count`·`actor`·`ref`가 단계 경로·재작업 되돌림·에스컬레이션·회수 참조를 복원하기에 충분해야 한다. 검증은 Verifier가 이 로그를 파싱해 전이 순서·완료 조건 충족·append-only 여부를 확인하는 방식이다(03 §7).
- **경계.** append-only·순서 확정의 물리 실현은 서술하지 않는다 — Adapter Binding 소관이다(§7). 본 절은 계약 수준 불변만 확정한다.

## §6. 회수 이력 기록 방식 — 결정 기록 (Advisor DP-L5)

**결정 (DP-L5).** Consult 단계의 전이 이벤트는 `ref` 필드에 **그 사이클의 회수 집합 참조**(Consult에서 수행된 Recall의 결과 집합 참조)를 기록한다.

**근거:**

- **(a) 03 §3.2-A `ref` 계약의 인스턴스(계약 확장 0).** `ref`의 계약 본문은 "관련 산출물·보고 참조"이며 DP-L5은 괄호 열거를 **예시(비한정)**로 해석한다. 회수 집합은 Consult 단계에서 수행된 회수(03 §5 Recall)의 결과이므로 그 단계의 "관련 산출물"에 포함된다 — 새 필드 0, `ref` 의미 재정의 0, 필수 표기 아니오 유지.
- **(b) 소관 배정의 해소 지점.** 회수 이력(작업별 회수 집합)의 저장 소관은 04 §9·05 §9 결정 기록에서 "03의 루프 상태 기록 소관, 05는 입력으로 받는다"로 기배정되었다. 본 기록 방식이 그 소관의 해소 지점이다 — 어느 전이 이벤트·어느 필드에 남는가를 확정한다.

**효과 (05 재발 판정 입력의 도출 전환):** 재발 판정(05 §3.1-C)의 `was_recalled`(05 §3.2-E) 입력은 종전 수동 제공을 전제했으나, Consult 전이 이벤트의 `ref` 회수 집합 참조가 그 판정 근거가 되어 **루프 상태 기록 기반 도출**로 전환된다. 05·04의 내부 포맷·판정 규칙·회수 집합의 **소비** 방식은 05·04 소관이며 § 포인터로만 참조한다.

**경계:** 회수 집합의 **내용**과 회수 정책(필요할 때만·목적 명시·최소 범위)은 03 §5·04·05 소관이다. 회수 집합 참조의 물리 표현은 Adapter Binding 소관이다(§7).

## §7. 경계와 비의존 — 직렬화·저장 위치 (Adapter Binding 소관)

- 루프 상태 기록의 **직렬화 형식·저장 위치·물리 경로**는 이 문서가 일절 확정하지 않는다. Core Contract(03 §3.2)는 추상 스키마이며 직렬화 형식은 Adapter Binding이 정한다(03 §3.2 도입·§4.1 루프 상태 기록 직렬화 행).
- `at`의 물리 시각 표현, `seq`의 물리 인코딩, 회수 집합 참조의 물리 표현, append-only의 물리 실현은 전부 Adapter Binding 문서 소관이며 `framework/adapters/<adapter>/` 뒤로 격리된다(03 §4.1·§4.2 SP-3; structure.md §2·§6). 이식 시 §2~§6의 필드·불변·회수 이력 기록 방식은 유지되고 물리 실현만 교체된다.
- 그 밖의 경계 선언(03 재정의 0·인스턴스화 대상·금지 토큰 규칙과 비대상 분류·07 R2·Glossary 정본)은 §0이 소유한다 — 금지 토큰 규칙 정본은 structure.md §5 C-3, 07 R2·R4 정본은 uahf/specs/07-workflow.md §3.2-C, 용어 정본은 uahf/specs/00-glossary.md다.
