# Commit Message Writer — 지시 본문 (body)

이 Skill은 하나의 작업 능력을 정의한다 — 변경 요약을 받아 커밋 메시지 초안을 낸다.

이 본문은 프로젝트 비의존이다. 프로젝트 특정 값(커밋 컨벤션·타입 목록·스코프 규칙·티켓/이슈 접두어·본문 언어·제목 최대 길이 등)은 Config(01 §3.2-B) 또는 `io.input`으로 주입되며 이 본문에 하드코딩되지 않는다 (INV-5).

## 입력 (io.input)

- `변경 요약` — 이번 커밋에 담긴 변경의 요약. 호출 Agent가 제공한다.
- (선택, 주입) 프로젝트 특정 값 — 커밋 컨벤션 스타일·허용 타입·스코프·이슈 접두어·언어·제목 길이 상한.

## 절차 (수행 단계)

1. **변경 요약 수신·정규화.** `io.input`의 변경 요약을 읽고, 서로 다른 관심사가 섞였는지 확인한다. 하나의 논리적 변경으로 좁힌다.
2. **변경 유형 식별.** 변경의 성격(기능 추가·결함 수정·문서·리팩터링·기타)을 식별한다. 유형 라벨의 정확한 표기·허용 목록은 주입된 컨벤션을 따른다(하드코딩 금지).
3. **제목 줄 작성.** 무엇이 바뀌었는가를 한 줄로 요약한다 — 명령형·간결·주입된 제목 길이 상한 안에서. 스코프·이슈 접두어가 주입되었으면 주입된 규칙대로만 부착한다.
4. **본문 작성(선택).** 변경의 배경(왜)과 핵심(무엇)을 필요 시 본문에 기술한다. 언어·상세 수준은 주입된 값을 따른다.
5. **초안 산출.** 위를 결합해 `io.output`의 커밋 메시지 초안으로 낸다.

## 출력 (io.output)

- `커밋 메시지 초안` — 제목 줄(+선택 본문)으로 구성된 초안. 이 산출물은 호출 Agent의 완료 보고(02 §3.2-C)에 반영된다.

## 경계 (역할·우선순위)

- 역할 경계 불침범·상위 규약 우선 → `uahf/specs/09-skills.md` §3.3 INV-2·INV-3 (재정의 0).
- 실제 커밋 실행·완료 판정은 이 Skill의 책임이 아니다 — 이 Skill은 초안만 낸다. 커밋 생성·검증·승인은 호출 Agent와 게이트의 소관이다.
