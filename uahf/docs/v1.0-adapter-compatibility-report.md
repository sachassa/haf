## §0. 이 문서의 위치·정본 경계

- **이 문서는 호환성 리포트다(인스턴스 정리).** 두 Adapter의 적합성 판정을 대조하고, 동일 Core Contract가 두 Adapter 모두에서 실현됨을 § 포인터로 정리한다. **판정 기준의 정본은 11 §3이고, 각 Adapter의 판정 정본은 각 Adapter의 Conformance 문서**(claude=`framework/adapters/claude/adapter-conformance.md` §3, generic=`framework/adapters/generic/generic-adapter-conformance.md` §3)다. 본 리포트는 그 판정을 **재정의·재판정하지 않고 인용·대조**한다.
- **판정 선취 없음(최종 승인 아님).** 본 리포트도 인스턴스 정리이며, 두 Adapter Conformance 판정에 대한 **최종 승인은 마일스톤 CP2(Verifier 독립 판정)·CP3(Advisor 최종 승인) 소관**이다(11 §7·02 §3.2-A). 상태 라인 "CP2 대기"가 이를 가리킨다. 본 리포트는 새 verdict·새 등급·새 판정 기준을 창설하지 않는다(§6).
- **DP-V14 — docs/ 문서의 자유 명명.** 본 문서는 docs/ 소속이므로 두 Adapter를 자유 명명(Claude Code·Generic)·경로 인용한다. generic 경계 산출물에 적용되는 명명 제약(DP-V6: 특정 AI/모델/벤더 제품명 0건, DP-V14: 타 Adapter 경로 불명명)은 **generic 경계 문서에만** 적용되며 docs/ 소속 호환성 리포트에는 적용되지 않는다. 따라서 본 문서는 첫 번째 Adapter의 구체 바인딩 값(모델명·`.claude/…` 경로·직렬화 형식명)을 인용해 대조할 수 있다.
- **실측 기반 상태 서술(L-07).** "실재/통과/0건" 주장 전건을 파일 시스템 직접 실측(파일 열거·라인 수·전수 스캔·판정 문서 인용) 후 기입했다. 미존재·미통과를 실재·통과로 쓰지 않는다.
- 용어는 specs/00-glossary.md 정본만 사용한다. Adapter Interface·바인딩 지점·Conformance·완전/최소 구현 Adapter·핵심 루프는 Glossary §3.2 정본이며 본 리포트는 그 대조만 한다. 새 용어를 신설하지 않는다.

## §1. 목적

이 문서는 UAHF의 두 Adapter가 **같은 Core 위에서 상호 호환됨** — 즉 Adapter Interface(11 §3.2-A)가 한 실행 환경(완전 Adapter)에서 다른 실행 환경(최소 구현 Adapter)으로 이식 가능하고, 그 이식이 Core Contract를 바꾸지 않음(INV-8) — 을 세 축으로 정리한다.

- **판정 대조(§2).** 두 Adapter의 Conformance Report(11 §3.2-D)를 나란히 놓아 등급(완전 ↔ 최소)·제공/생략 바인딩을 대조한다.
- **동일 Core Contract 시연(§3).** 같은 핵심 루프가 두 Adapter 모두에서 통과하고, 두 통과가 소비한 Core Contract가 동일함을 실증한다(INV-8·11 §8 예2).
- **Core 무수정 시연(§4)·바인딩 값 대조(§5).** 두 Adapter가 공존하는 현 시점에 Core 경계가 AI 의존 요소 0을 유지하고 어느 Adapter도 Core를 수정하지 않았음을 실측하며(11 §7), 무엇이 교체되고(BP 값) 무엇이 유지되는지(Core Contract)를 13 BP 단위로 구분한다(11 §4.2).

본 문서는 11 §3의 어떤 계약 요소도, 각 Adapter Conformance 문서의 판정도 재정의·재판정하지 않는다(§0·§6).

## §2. 두 Adapter 대조 표 (완료 조건 근거 — v1.0 완료 조건 ①)

두 Adapter의 Conformance Report(11 §3.2-D)를 대조한다. 각 값은 해당 Adapter Conformance 문서 §3이 소유하며, 아래는 그 인용이다(재정의 0).

| Adapter | verdict | 등급 (11 §3.2-B) | 제공 바인딩 | 생략 바인딩 | 판정 정본 |
|---|---|---|---|---|---|
| **Claude Code** (첫 번째 Adapter) | **Valid(Full)** | **완전 Adapter (Full Adapter)** | **17 BP 전건** — 필수 13(BP-1·2·3·4·5·7·8·9·10·11·13·14·15) + 선택 4(BP-6·12·16·17) | 없음 | `framework/adapters/claude/adapter-conformance.md` §3 (verdict=Valid(Full)·notes 선택 4종 전건 제공) |
| **Generic** (두 번째 Adapter) | **Valid(Minimal)** | **최소 구현 Adapter (Minimal Adapter)** | **필수 13** — BP-1·2·3·4·5·7·8·9·10·11·13·14·15 | **선택 4** — BP-6(확장 표면)·BP-12(영속성 백엔드)·BP-16(이벤트·Hook Dispatch)·BP-17(적용 조건 매칭) | `framework/adapters/generic/generic-adapter-conformance.md` §3 (verdict=Valid(Minimal)·notes 선택 4종 미제공) |

주:

- **공통 합격선(C1~C3).** 두 Adapter 모두 C1(필수 바인딩 완전성)·C2(Core Contract 불변)·C3(핵심 루프 통과)을 만족한다(11 §3.1). 즉 **필수 13 BP 전건 제공 + Core 수정 0 + 핵심 루프 1회 통과**가 두 Adapter의 공통 기반이며, 이 부분집합이 곧 최소 바인딩 부분집합(11 §3.2-B 정본)이다.
- **등급 차이 = 선택 4 BP.** 두 Adapter의 유일한 등급 차이는 선택 바인딩(BP-6·12·16·17)의 제공 여부다. 첫 번째 Adapter는 이 4종을 기능 완성 수준으로 제공(완전)하고, Generic Adapter는 최소 구현 Adapter로서 생략(11 §3.2-B가 명시적으로 허용 — generic-binding.md §3·generic-adapter-conformance.md §3 notes). **필수 13 BP는 두 Adapter가 동일하게 제공**한다.
- **판정 대상 정합.** 최소 구현 Adapter 판정 기준(11 §3.2-B 최소 바인딩 부분집합 13)은 v1.0 2nd Adapter 판정의 정본 합격선이며, Generic Adapter가 이 부분집합 전건을 제공하고 C2·C3을 만족하여 Valid(Minimal)로 판정됐다(11 §8 예1과 정렬). 이로써 Adapter Interface가 다른 실행 환경에 적용 가능함이 실증된다(Architecture Validation).

## §3. 동일 Core Contract 시연 (INV-8 · 11 §8 예2)

11 §3.3 INV-8("동일 Core Contract는 두 Adapter 모두에서 그대로 실현된다. Adapter 교체가 Core를 바꾸지 않는다")과 11 §7 "동일 Core Contract 시연"을 실증한다. 같은 핵심 루프(위임 → 구현 → 검증 → 승인)가 두 Adapter 모두에서 통과했고, 두 통과가 **소비한 Core Contract가 동일**함을 § 포인터로 대조한다.

### §3.1 두 Adapter 위에서의 핵심 루프 통과

| 통과 | Adapter | 실증 근거 (실측) |
|---|---|---|
| **(a)** | 첫 번째 Adapter (Claude Code) | 핵심 루프가 v0.2 Agent Harness Bootstrap 이래 반복 통과했다 — 검증 리포트 `docs/v0.3~v0.9-verification-report.md` **7건 실재**(각 마일스톤 위임→구현→독립 검증→승인 통과). v1.0 실증: `framework/adapters/claude/loop-data/v10-dogfooding.jsonl` **7 line**(Consult→…→Complete 완주·retry_count 0·actor=human 0)이 Dogfooding 개발 사이클(위임→구현→독립 Verifier CP2 Pass→승인) 1회 통과를 기록(`docs/v1.0-dogfooding-report.md` §6·§8). |

| 완료 보고 5필드 | 02 §3.2-C | 완료 보고(CP1) 5필드(dogfooding §6.2·loop-data seq4 completion-report-cp1) | `channels/completion-report.md` — 완료 보고 5필드(demo §3.3) |

## §4. Core 무수정 시연 (11 §7)

11 §7 "Core 무수정 시연"("두 Adapter 교체 전후 Core 디렉터리 diff가 0이고, Core에 AI 의존 요소가 0건임을 보인다")을, 두 Adapter 경계가 공존하는 현 시점 실측으로 실증한다.

### §4.1 Core 경계 AI 의존 요소 0건 — 전수 스캔 (후보 집합 명시)

Core 경계인 `framework/core/`(2문서: structure.md·config-schema.md)·`framework/runtime/`(3문서: lifecycle.md·module-manifest.md·module-registry.md) **5문서 전건**을 대상으로, 후보 집합 전체를 대소문자 무시로 전수 스캔했다(2026-07-06 직접 실측). 단일 대리 지표 하나로 결론짓지 않고 후보 집합 전체를 대상으로 확인했다(06 §3.1 V4·BP-01).

| 후보 집합 카테고리 | 대표 토큰(예) | 스캔 결과 (5문서) |
|---|---|---|
| (a) 특정 대화형 AI 제품명 | claude, chatgpt, copilot, cursor, bard | **0건** |
| (b) 특정 모델 계열명 | opus, sonnet, haiku, gpt-N, o1, llama, mistral | **0건** |
| (c) AI 벤더명 | anthropic, openai, google/deepmind, cohere | **0건** |
| (d) 특정 하위 실행 단위 기능명·설정 디렉터리 제품 표기 | subagent/서브에이전트, `.claude`, settings.json, front-matter | **0건** |
| (e) 특정 언어·툴체인·직렬화 형식명 | python, node, npm/pip, javascript, json/yaml/jsonl, markdown | **0건** |

- **판정: Core 경계 AI 의존 instance 토큰 0건.** 다섯 카테고리 전건 0건(structure.md §5 C-3, 01 §3.3 INV-4). Core 경계는 AI 비의존·언어/툴체인 비의존 계약·스키마 문서만 담는 상태를 유지한다. 이는 각 Adapter Conformance 문서의 C2 판정과 정합한다(claude=adapter-conformance.md §3.1 C2, generic=generic-adapter-conformance.md §2.2).

### §4.2 두 Adapter 어느 쪽도 Core를 수정하지 않음 (변경 이력 대조)

- **바인딩 산출물의 물리 격리.** 첫 번째 Adapter의 산출물(`framework/adapters/claude/` 15엔트리)과 두 번째 Adapter의 산출물(`framework/adapters/generic/` — generic-binding.md·generic-adapter-conformance.md, 그리고 docs/ 소속 시연 기록·픽스처)은 전부 Core 경계(`framework/core/`·`framework/runtime/`) 밖에 물리 격리된다(structure.md §2·§3 규칙 3, 11 §3.3 INV-3). 어느 Adapter의 바인딩 값·판정 산출물도 Core Contract 문서를 수정·확장·삭제하지 않는다.
- **Core Contract 불변(01 §3).** 각 Adapter의 C2 판정이 Core Contract 수정 0건을 확립한다 — 첫 번째 Adapter는 v0.3~v0.8 각 마일스톤 CP2 독립 판정이 Core 무변경을 실측했고(adapter-conformance.md §3.1 C2), 두 번째 Adapter는 Core 경계 전수 스캔 0건 + Generic 경계 Core 무침범으로 확립됐다(generic-adapter-conformance.md §2.2).
- **변경 이력 주(정직).** Core 경계 문서 중 구조 규격 문서(structure.md)의 §8 트리 절이 어댑터 경계 파일을 열거하도록 격리 개정된 이력이 있으나(structure.md §9 — v0.9 T8 등), 각 개정은 파일 시스템 실측 반영이며 매 개정이 **"01 §3 계약 재정의 0"**을 명시한다(structure.md §9 이력·§0 정본 경계). 즉 Core **Contract(01 §3)** 자체는 불변이며, 트리 열거 갱신은 계약 수정이 아니라 실측 반영이다.
- **결론(11 §8 예2 결론 인스턴스).** 교체 대상은 §5의 바인딩 지점 값(첫 번째 Adapter 값 → Generic 값)뿐이었고, Core 디렉터리의 Core Contract는 불변이며 AI 의존 요소는 0건이다. 따라서 **"Adapter만 교체하면 이식된다"가 성립한다**(ARCHITECTURE.md 3.1, 11 §3.3 INV-8, 11 §8 예2 결론).

## §6. 판정 선취 없음 · 정본 경계 (self-note)

- **판정 선취 없음(최종 승인 아님).** 본 리포트는 두 Adapter Conformance 판정의 **인스턴스 정리·대조**이며, 판정을 재산출·재판정하지 않는다. 두 Adapter의 verdict(Valid(Full)·Valid(Minimal))는 각 Adapter Conformance 문서 §3이 소유하고, 본 리포트는 그것을 인용한다. 이 판정들에 대한 **최종 승인은 마일스톤 CP2(Verifier 독립 판정)·CP3(Advisor 최종 승인) 소관**이다(11 §7·02 §3.2-A). 상태 라인 "v1.0 Draft (CP2 대기)"가 이를 명시한다.
- **재정의·창설 0.** 본 문서는 11 §3의 어떤 계약 요소(바인딩 지점·판정 조건 C1~C3·Report 필드·verdict 값·등급 기준·불변 규칙)도, 각 Adapter Conformance 문서의 판정도 재정의·재판정하지 않는다. **새 BP·새 Report 필드·새 verdict 값·새 등급·새 용어를 창설하지 않았다.** 모든 대조 값은 정본(11 §3·§4.1, 각 Adapter Conformance/Binding 문서, demo/dogfooding 기록)의 인용이다.
- **실측 기반 서술(L-07).** §2 판정 값·§3 loop_pass 근거(검증 리포트 7건·loop-data 7 line·cycle-record 4전이·독립 검증 Pass)·§4 Core 경계 5문서 전수 스캔 0건·§5 BP 값은 전부 파일 시스템 직접 실측·판정 문서 인용 후 기입했다. 실측·인용과 불일치하는 서술은 0건이다.
- **소유 경계 준수(07 R4·INV-2).** 본 산출은 이 1개 파일(`docs/v1.0-adapter-compatibility-report.md`)만 생성한다(본 Task 산출물 2/2 — 산출물 1은 `framework/adapters/generic/generic-adapter-conformance.md`). 두 Adapter 경계(`framework/adapters/claude/`·`framework/adapters/generic/`)·`framework/core/`·`framework/runtime/`·specs/·기존 docs/ 문서·라이브 표면을 수정·생성하지 않는다. 인용한 판정 문서·바인딩 문서·시연 기록은 읽기 전용 소비.
- **동시 작성 문서 불인용(07 R2).** 동시 작성 중인 형제 Task 산출물(structure.md 개정분·getting-started.md 개정분)을 인용·추측하지 않았다. structure.md는 v0.9 Baseline 문면(§2·§5·§8·§9)까지만 참조했다. 참조한 확정 정본은 Frozen specs(11·02·00)·Baseline/확정 판정·바인딩 문서(claude adapter-conformance·generic-adapter-conformance·generic-binding)·확정 시연 기록(demo·dogfooding·검증 리포트 7건·v10-dogfooding.jsonl)·AGENT.md·docs/delegation-protocol.md뿐이다.
