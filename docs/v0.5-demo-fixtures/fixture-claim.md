# [시연 픽스처 — 실계약 문서 아님] fixture-claim — Worker 완료 보고 claim (좁은 범위 검사 주장)

> **시연 픽스처 — 실계약 문서 아님.** 이 파일은 v0.5 Verifier 시연(Task V8, 시연 ⓐ·ⓕ)을 위해 구성된 **Worker 완료 보고 claim**이다 (06 §8 예1 동형). 실제 완료 보고가 아니라, 시연의 **참고 입력(claim)** 으로 쓰이는 구성물이다. 이 claim의 주장은 판정의 **참고 입력일 뿐 판정 근거가 아니다** (06 V1, INV-1). `docs/v0.5-demo-fixtures/` 내부에만 존재한다.

## 완료 보고 claim (02 §3.2-C 필드 형태 — 시연용 구성물)

| 필드 (02 §3.2-C) | claim 값 |
|---|---|
| `artifacts` | `docs/v0.5-demo-fixtures/fixture-target.md` |
| `self_check` | 대상 파일 §2(연산 서술) 경계에 **AI 의존 요소 0건 — 충족** |
| `failures` | 없음 |
| `open_questions` | 없음 |
| `verify_basis` | 대상 파일 본문에서 **특정 AI 어시스턴트 이름 문자열 1종(부류 ①의 한 토큰)만 단일 토큰 검색**하여 0건 매치 → "AI 의존 0건"으로 결론. |

## 주 (claim의 지위와 좁은 범위)

- 이 claim의 `self_check` "충족"은 **좁은 범위(단일 토큰 1종) 검사**에 근거한다 — 후보 부류 **전체**(① 특정 AI 이름·모델명·제품 기능명 / ② 언어·툴체인 / ③ 직렬화·확장자·OS / ④ 물리 경로·인스턴스)에 대한 **전수 스캔이 아니다**.
- claim이 검색한 토큰(어시스턴트 이름 1종)은 대상 파일에 실제로 **부재**하므로 "그 토큰 0건"은 **정직**하다. 그러나 claim은 이를 "AI 의존 0건"으로 **과잉 일반화**하여, 검색한 토큰과 **다른 형태**의 부류 ① 토큰(§2의 모델명)을 **놓친다** (06 §8 예1의 실패 유형 — 검사 범위 부족).
- 판정(시연 ⓐ·ⓕ)은 이 claim을 신뢰하지 않고 산출물(fixture-target.md) 자체를 **충분한 범위로 전수 재검사**한다 (06 V1·V4, §3.2-F).
