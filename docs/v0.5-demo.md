### §0.2 시각 서술 성격 구분 (L-07 재발 방지, V7 §3 기록 요건 2, done 5)

- 이 기록은 시연 **단계 순서**를 **순서 값(단계 번호 1·2·3…)** 으로만 서술한다. 시연 각 단계에 대해 "실제 수행 시각" 류의 **벽시계 timestamp 주장을 넣지 않는다** — 넣지 않았음을 여기 명시한다.
- 물리 생성/수정 시각이 필요한 자리(생성 산출물, §8)에는 **파일 시스템 실측(LastWriteTime)** 값만 기입하고, 이를 "**물리 생성/수정 시각 (파일 시스템 실측)**"으로 명시해 순서 값과 성격을 구분한다. 순서 값(단계 번호)과 물리 생성 시각(실측)을 혼동하지 않는다.
- Memory index.jsonl의 `timestamp` 필드(예: `2026-07-05T22:19:47.602+09:00` 부류의 연속 +.001s 값)는 **생성기 배정 순서 값(정합 순서)** 이며 물리 수행 시각이 아니다(memory-binding §5.4·§7 관례). 이 기록은 그 값을 "실제 수행 시각"으로 서술하지 않는다.

### §0.3 픽스처 격리 기록 (done 7)

- 심은 금지 토큰: **부류 ①(특정 AI 이름·모델명·제품 기능명) 중 특정 모델명 1건**을 `fixture-target.md` §2 본문에 심었다. 본 기록은 그 원문 토큰을 **재현하지 않고** "위치·부류" 수준으로만 서술한다(잔존 위치 = fixture-target.md §2 / 부류 = ① 특정 모델명).
- 격리 실측: 저장소 전역 텍스트 검색 결과 심은 토큰은 `docs/v0.5-demo-fixtures/fixture-target.md`에 **정확히 1건**만 존재하고, 픽스처 디렉터리 **밖에는 0건**이다(이 demo.md 본문 포함 0건). 시연 산출물(픽스처 2파일·검증 리포트 인스턴스 5파일·이 기록)은 전부 소유 경계(`docs/v0.5-demo.md` + `docs/v0.5-demo-fixtures/`) 내부에 있다. `framework/`·`specs/`·기존 `docs/` 파일 수정 0건.
- 픽스처 디렉터리는 06 §7-⑧ Core AI 비의존 전수 스캔(CP2 소관)의 대상 경계에서 제외되는 정당 보유 지점이다(V7 §4.2) — 심은 토큰이 실계약 경계의 위반으로 계상되지 않는다.

## §1. 공통 사항

- **판정 값·최종 판정 정본:** 관측 결과의 판정 값(충족/위반/판정 불가)은 06 §3.2-B·verification-report §3, 리포트의 최종 판정(통과/실패/조건부)은 06 §3.2-C·verification-report §4다. 이 기록은 관측·기록까지만 하며, 최종 승인·재작업 여부 판단은 게이트(CP2 Verifier·CP3 Advisor) 소관이다 — 자기 점검·시연 산출은 최종 승인이 아니다(02 §3.2-A, V7 §7-3).
- **음성/양성 구분(V7 §7-5):** ⓐ(위반 검출 기대)·ⓓ(Fail·Conditional 분기 기대)처럼 위반/비통과를 **기대**하는 시연은, 그 기대된 검출·거부가 정확히 관측되면 **시연 관측 결과 = 충족**이다. 이때 리포트의 `final_verdict`(Fail/Conditional)와 시연 관측 결과(충족)는 서로 다른 대상의 값이다 — 혼동하지 않는다.
- **수행 물리 지점 표기(V7 §5, verifier-binding §5 참조):** 파일 조회 = Read(verifier-binding §5 VT-1/VT-2/VT-3·§2 행4 회수), 텍스트 검색(전수 스캔) = Grep(§5 VT-4), 명령 실행(시연 재현·재계산) = PowerShell/Bash(§5 VT-5). 검증 리포트 직렬화 = 구조화 Markdown 6필드 절 구조(verifier-binding §4.1). 단, 저장 위치는 Advisor 운용 지정에 따라 `docs/v0.5-demo-fixtures/`이며 `docs/v0.5-verification-report.md`(CP2 전용)를 사용하지 않았다.
