## §0. 이 문서의 위치와 정본 경계

- **정본은 specs/03-loop.md §3.1-A이다.** 이 문서는 그 단계 전이 규칙(7단계 진입/활동/완료/전이/실패 + 게이트-단계 매핑)의 **인스턴스**이며, 규칙을 재정의·확장하지 않는다. 계약 요소는 § 포인터로만 참조한다(framework/core/structure.md §7 확정 조건 C-1 정합 — 인스턴스는 계약 변경이 아니다).
- 이 문서는 `framework/loop/` 아래 **단계 전이 규칙**을 확정한다. 03 §3.1-A의 7단계 규칙과 게이트-단계 매핑을 이 경계 위에 배치·대조하되, 각 셀의 진위 판정 기준은 03 §3.1-A 정본이 유지한다(loop-state-record.md §0·verifier-protocol.md §0 정본 경계 관례 동형).
- **이 문서는 Module 구현 디렉터리 문서다.** `framework/loop/`는 structure.md §2가 지정한 Module 구현 디렉터리 경계다. 본문 전체에 특정 AI 이름·모델명·제품 기능명·프로그래밍 언어명·툴체인명·직렬화 형식명·물리 경로·확장자를 두지 않는다(structure.md §5 C-3 확장, 03 §3.3 INV-9).
- **인스턴스화 대상 경계.** 본 문서의 인스턴스화 대상은 03 §3.1-A **단계 전이 규칙**(7단계 진입/활동/완료/전이/실패 + 게이트-단계 매핑)이다. **재작업 루프(03 §3.1-B)·종료 규칙(03 §3.1-C)·사람 개입 지점(03 §3.1-D)의 상세는 인스턴스화 대상이 아니며** 03 정본 § 포인터로만 참조한다(재정의·확장 0). 다만 각 단계의 **실패 분기**가 이들 § 포인터(재작업 루프·에스컬레이션)로 연결됨은 §2.1이 03 문면 그대로 서술한다.
- **사이클 구동 연산 경계.** 사이클 구동 연산(03 §3.1 입출력·재작업 루프 구동·종료·에스컬레이션)의 상세는 그 **인스턴스 문서 소관**이다. 본 문서(03 §3.1-A 단계 전이 규칙의 인스턴스)는 그 소관을 침범하지 않고, 필요한 자리에는 일반 포인터(03 §3.1)로만 구분한다.
- **Verify 판정 내용 비정의(06 INV-9).** 본 문서는 Verify 단계의 시점·전이·시퀀싱을 배열한다(03 §3.1-A 인스턴스). 그러나 CP2(Verifier 독립 판정)의 판정 **기준·방법·내용**은 정의하지 않는다 — 06 소관이며 § 포인터로만 참조한다(§3).
- **전이 기록 포맷 비정의.** 전이 이벤트의 필드·스키마·append-only 불변의 **포맷**은 본 문서가 정의하지 않는다. 포맷 정본은 03 §3.2-A와 형제 확정본 framework/loop/loop-state-record.md가 소유한다(§4).
- **03 내부 § 포인터 표기 관례.** 03 정본 셀을 보존할 때, 03의 내부 § 포인터는 `03 §…` 접두로 명시하여 본 문서 자신의 절 번호와 구분한다. 이는 셀의 대상 지시를 명료화하는 표기이며 셀 내용(문안·전이 대상·실패 분기)을 변경하지 않는다(loop-state-record.md §0·verifier-protocol.md §0의 내부 § 포인터 표기 관례와 동형). 외부 문서 포인터(02 §…, 06 §…, AGENT.md, Glossary §…)와 단계·역할 명칭은 정본 그대로 둔다.
- 용어는 specs/00-glossary.md 정본(§3.2-J J-03: 단계 전이·루프 상태 기록·재작업 루프)만 사용한다. 새 용어를 신설하지 않는다. "게이트-단계 매핑·검증 게이트·체크포인트(CP1~CP3)"는 03 §3.1-A 정본이 정의한 서술 명칭이며 본 문서가 신설한 용어가 아니다.

## §1. 목적

`framework/loop/`의 이 규격은 네 가지를 확정한다.

- **단계 전이 규칙** — 성공 경로 7단계(Consult → Plan → Execute → Verify → Learn → Memory Update → Complete) 각각의 진입 조건·활동·완료 조건·전이·실패 분기를 03 §3.1-A 정본 셀 단위로 인스턴스화한다(§2.1).
- **게이트-단계 매핑** — 검증 게이트 CP1 → CP2 → CP3의 단계 배치와 소유, "Verify 통과 = CP2 PASS" 정의, 02 INV-4 정렬을 보존한다(§2.2).
- **06 INV-9 양방향 정합** — Verify 단계의 시점·전이·시퀀싱은 03(과 본 문서 인스턴스)이 소유하고, CP2 판정의 기준·방법·내용은 06 소관임을 양방향으로 명시한다(§3).
- **전이 기록 의무** — 모든 단계 전이가 루프 상태 기록에 append-only로 남는다는 의무(03 INV-3)를 명시하고, 기록 포맷은 03 §3.2-A·framework/loop/loop-state-record.md에 위임한다(§4).

이 규격은 03 §3.1-A Core Contract의 **인스턴스**다. 단계 전이 규칙·게이트 배치·전이 기록 의무를 재정의·확장하지 않는다. 형태 A(문서)에서 형태 B(실행 코드)로 전환되어도 03 §3 Core Contract 변경은 0이며, 위반(형태 B가 03 §3 계약을 바꾸어야만 성립하는 경우)이 발견되면 구현하지 않고 Advisor에게 보고한다(structure.md §7 C-1과 같은 불변 원칙).

## §2. 단계 전이 규칙 인스턴스 (정본: 03 §3.1-A)

Loop는 성공 경로에서 7단계를 선형 순서로 전이한다.

Consult → Plan → Execute → Verify → Learn → Memory Update → Complete (AGENT.md, Glossary §3.2-F).

각 단계는 진입 조건이 충족될 때만 진입한다. 완료 조건이 충족될 때만 다음 단계로 전이한다. 모든 전이는 루프 상태 기록(03 §3.2-A)에 남는다 (03 INV-3). 각 단계의 실패는 재작업 루프(03 §3.1-B) 또는 에스컬레이션(03 §3.1-C)으로 분기한다.

### §2.1 7단계 진입·활동·완료·전이·실패 (셀 단위 일치 — 정본 03 §3.1-A)

아래 7단계 각각의 **진입 조건·활동·완료 조건·전이·실패(분기)** 항목은 03 §3.1-A 정본을 **그대로 보존**한다(자구 왜곡 0, 재정의 0, 새 규칙·새 전이 0). 각 단계의 각 항목이 03 §3.1-A의 대응 셀과 자구 단위로 일치한다. 03의 내부 § 포인터만 `03 §…` 접두로 명시하며(§0 표기 관례), 이는 셀의 대상 지시를 명료화할 뿐 셀 내용을 바꾸지 않는다. 외부 문서 포인터(02 §…, AGENT.md, Glossary §…)와 단계·역할 명칭·의무 라벨(02 O4·02 INV-6 등)은 정본 그대로 둔다. 03 정본이 "02 §…" 뒤에 이어 쓴 축약 포인터(Plan 활동의 "INV-3", Verify CP2의 "§3.1")는 선행 "02" 문맥을 잇는 02 내부 포인터이며, 정본 문면 그대로(축약 그대로) 보존한다 — 임의로 "02"를 덧붙이거나 "03 §"로 바꾸지 않는다(자구 왜곡 0). "03 §…" 접두는 03 자신의 내부 포인터에만 적용한다.

**1. Consult**
- 진입 조건: 위임 메시지가 완전하다 (02 INV-6 — 입력·출력·완료 조건·컨텍스트 존재). 불완전하면 진입하지 않고 반환·질의한다.
- 활동: 상위 규약·Architecture·관련 spec·Memory를 참조한다. Advisor가 참조를 주도한다 (02 §3.1). Memory 회수는 회수 정책에 따라 최소 범위로 한다 (03 §5).
- 완료 조건: 착수에 필요한 컨텍스트가 확보된다.
- 전이: → Plan.
- 실패: 컨텍스트 부재·의존 계약 미확정으로 추측 없이 진행 불가 → 에스컬레이션 (02 O4, 03 §3.1-D 조건 3).

**2. Plan**
- 진입 조건: Consult 완료.
- 활동: 작업을 계획·분해한다. Planner가 초안을 작성하고 Advisor가 채택한다 (02 §3.1, INV-3).
- 완료 조건: Advisor가 계획을 채택한다.
- 전이: → Execute.
- 실패: 계획 미채택 → Plan 재작성. 반복 미채택 → 에스컬레이션.

**3. Execute**
- 진입 조건: Plan 채택 완료.
- 활동: Worker가 계획을 구현하고 산출물을 생성한다 (02 §3.1).
- 완료 조건: 산출물이 생성되고 Worker 자체 점검(self_check, 02 §3.2-C)이 수행된다. 자체 점검은 최종 승인이 아니다 (02 §3.2-A Worker 경계).
- 전이: → Verify.
- 실패: 구현 불가·차단 → 실패 보고(02 §3.2-D) → 재작업 루프 또는 에스컬레이션.

**4. Verify** (오케스트레이션 순서만 정의 — 판정 내용은 06 소관)
- 진입 조건: Execute 완료 (산출물 + 자체 점검 존재).
- 활동: 검증 게이트를 오케스트레이션한다. 게이트는 Loop가 소유하는 순서 있는 세 체크포인트다.
  - CP1. Worker 자체 점검 — Execute 산출을 입력으로 받는다.
  - CP2. Verifier 독립 판정 — Worker 보고를 그대로 신뢰하지 않고 독립 판정한다 (02 §3.2-A, §3.1). 판정 기준·검증 방법은 06 소관이다.
  - CP3. Advisor 승인 — 최종 승인 (02 §3.1). CP3는 Complete 전이 게이트로 실현된다(아래 "게이트-단계 매핑" 참조).
- 완료 조건(Verify 통과): CP2가 PASS다. Verify 통과 후에만 완료 보고가 생성될 수 있다 (02 INV-4).
- 전이(통과): → Learn.
- 전이(실패): CP1 또는 CP2 실패 → 재작업 루프(03 §3.1-B).
- 경계: Loop는 CP1 → CP2 → CP3 순서만 소유한다. 각 체크포인트의 판정 내용은 CP1·CP3가 02(Worker·Advisor), CP2가 06(Verifier) 소관이다.

**5. Learn**
- 진입 조건: (a) Verify 통과(성공 경로), 또는 (b) 사이클이 에스컬레이션으로 종료되기 직전(실패 경로). 두 경우 모두 Learn을 거친다 (03 INV-5).
- 활동: 실패와 성공에서 후보를 도출한다 (03 §3.2-C). Verifier가 Learn 입력을 제공한다 (02 §3.1).
- 완료 조건: 이 사이클의 Lesson 후보(누적 실패)와 Best Practice 후보(성공 시)가 도출된다.
- 전이: → Memory Update.
- 실패: 없음(도출만 수행). 후보가 없으면 "없음"을 기록한다.

**6. Memory Update**
- 진입 조건: Learn 완료.
- 활동: Learn이 도출한 후보를 기록한다. 모든 접근은 Memory Service Interface(단일 Port) 경유다 (03 §5, 03 INV-7).
- 완료 조건: 후보가 단일 Port를 통해 기록된다. 내부 포맷·승격은 04/05 소관이다.
- 전이(성공 경로): → Complete. 전이(실패 경로): → 에스컬레이션(03 §3.1-C).
- 실패: Port 접근 불가 → 에스컬레이션.

**7. Complete**
- 진입 조건: Memory Update 완료 + 검증 게이트 CP1·CP2 통과.
- 활동: CP3(Advisor 최종 승인, 02 §3.1)을 게이트로 삼아 사이클을 닫고 완료 보고 메시지(02 §3.2-C)를 산출한다.
- 완료 조건: Advisor가 최종 승인한다. 미승인 시 재작업 루프(03 §3.1-B) 또는 에스컬레이션.
- 전이: 사이클 종료(정상).

**셀 형태 보존 주(비계약).** 03 §3.1-A 정본은 단계마다 항목 표기가 다르다 — Verify는 "전이(통과)/전이(실패)"와 별도 "경계" 줄을, Memory Update는 "전이(성공 경로)/전이(실패 경로)"와 별도 "실패" 줄을, Complete는 별도 "실패" 줄 없이 완료 조건 안에 실패 분기(미승인 시 재작업 루프/에스컬레이션)를 둔다. 본 절은 이 문면 차이를 정본 그대로 보존하며 항목을 임의로 통일·추가하지 않는다(자구 왜곡 0). 각 단계 실패 분기는 위 문면대로 재작업 루프(03 §3.1-B) 또는 에스컬레이션(03 §3.1-C·§3.1-D)의 소관 § 포인터로 연결된다(상세는 그 §가 소유 — §0 인스턴스화 대상 경계).

### §2.2 게이트-단계 매핑 (정본: 03 §3.1-A "게이트-단계 매핑")

아래 표와 정렬 서술은 03 §3.1-A "게이트-단계 매핑" 정본을 그대로 보존한다(재정의 0). 검증 게이트 CP1 → CP2 → CP3의 단계 배치와 소유다.

**게이트-단계 매핑 (검증 게이트 CP1→CP2→CP3의 단계 배치).**
Loop는 세 체크포인트의 순서를 불변으로 소유한다. 각 체크포인트는 다음 단계에 배치된다.

| 체크포인트 | 배치 단계 | 소유(내용) |
|---|---|---|
| CP1 Worker 자체 점검 | Execute 종료 → Verify 입력 | 02 (Worker) |
| CP2 Verifier 독립 판정 | Verify | 06 (Verifier) |
| CP3 Advisor 승인 | Complete 진입 게이트 | 02 (Advisor 최종 승인) |

이 배치는 02 §3.1(Verifier 판정 = Verify, Advisor 최종 승인 = Complete)과 02 INV-4(완료 보고는 Verify 통과 후)에 정렬한다. "Verify 통과"는 CP2 PASS로 정의된다. Advisor 최종 승인(CP3)은 Complete 게이트다. 정합 확인은 03 §9에 기록한다.

**정렬 명시(done 대조 지점).** 위 매핑은 다음을 명시한다 — (i) "Verify 통과 = CP2 PASS" 정의(완료 조건 "CP2가 PASS다"의 게이트 실현, §2.1 Verify), (ii) 02 INV-4(완료 보고는 Verify 통과 후에만 생성)와의 정렬 — Verify 통과(CP2 PASS) 전 완료 보고는 무효이며, 이는 03 INV-2(검증 게이트: 완료 보고는 Verify 통과=CP2 PASS 후에만 생성)와도 정합한다. (iii) CP1은 Execute 종료→Verify 입력에 배치되고 02(Worker) 소관, CP2는 Verify에 배치되고 06(Verifier) 소관, CP3는 Complete 진입 게이트에 배치되고 02(Advisor 최종 승인) 소관이다. 정합 확인은 03 §9 결정 기록("게이트-단계 매핑 승인")에 확정되어 있다.

## §3. 06 INV-9 정합 — Verify 시점·전이 소유 ↔ CP2 판정 내용 소관 (양방향)

06 INV-9는 "Verify 단계의 시점·전이·시퀀싱은 정의하지 않는다 (03-loop 소관). Verifier는 판정 기준·검증 리포트·독립성 계약만 소유한다"고 규정한다. 본 문서는 이 경계를 **양방향**으로 명시한다.

- **방향 1 — 시점·전이·시퀀싱은 03(과 본 문서 인스턴스)이 소유한다.** Verify 단계가 Lifecycle에서 언제 진입하고(진입 조건: Execute 완료 — 산출물 + 자체 점검 존재), 어디로 전이하며(전이(통과) → Learn / 전이(실패) → 재작업 루프 03 §3.1-B), 검증 게이트를 어떤 순서로 시퀀싱하는지(CP1 → CP2 → CP3의 불변 순서)는 03 §3.1-A가 소유하고, 본 문서가 그 인스턴스로서 배열한다(§2.1 Verify, §2.2). 06은 이 시점·전이·시퀀싱을 정의하지 않는다(06 INV-9).
- **방향 2 — CP2 판정의 기준·방법·내용은 06이 소관한다.** CP2(Verifier 독립 판정)에서 무엇을 근거로·어떤 대조 기준으로·어떤 방법으로 판정하는가(판정 기준 카탈로그·검증 리포트·독립성·거짓 완료 보고 검출)는 06 소관이다(06 §3.1·§3.2, §3.3 INV-1~INV-10). 본 문서는 CP2의 판정 내용을 정의·재서술하지 않고 06 § 포인터로만 참조한다. §2.1 Verify 활동의 "판정 기준·검증 방법은 06 소관이다"와 경계의 "CP2가 06(Verifier) 소관"이 이 위임을 03 정본 문면 그대로 보존한다.

이 양방향 경계는 06 §9-OQ-V1(03-loop 조율 — "세 행위의 시점·전이·시퀀싱은 06이 정의하지 않는다, 03-loop 소관")과 06 §9 결정 기록(OQ-V1: 03 §3.1-A 게이트-단계 매핑과 대조 — 정합 확인 완료)에 정합한다. 순서(03) ↔ 판정 내용(06)의 분리는 순환이 아니라 위임이다(03 §2 경계(위임) 관계, 06 순환 의존 없음). 본 문서는 06의 판정 기준·리포트·독립성 계약의 내용을 추측·인용하지 않고 소관 § 포인터로만 가리킨다.

## §4. 전이 기록 의무 (정본: 03 §3.2-A·INV-3; 포맷: framework/loop/loop-state-record.md)

- **의무.** 모든 단계 전이는 루프 상태 기록에 append-only로 남는다. 기록되지 않은 전이는 없다(03 INV-3). §2.1의 성공 경로 선형 전이(각 단계 → 다음 단계)와, 각 단계 실패 분기가 유발하는 재작업 되돌림(03 §3.1-B)·에스컬레이션 전이는 **모두** 이 기록 대상이다(03 §3.1-A 도입 "모든 전이는 루프 상태 기록에 남는다", 03 §3.2-A). 전이는 기록된 뒤에 유효하며, 이 기록만으로 사이클 전체를 재구성·검증할 수 있어야 한다(03 §3.2-A 불변 규칙, 03 §7).
- **포맷 비재정의.** 전이 이벤트의 필드·스키마·단계 상태·append-only 불변의 **포맷 자체**는 본 문서가 재정의하지 않는다. 그 포맷은 형제 확정본 framework/loop/loop-state-record.md(전이 기록 포맷의 소유 문서)와 03 §3.2-A 정본이 소유하며, 본 문서는 저장소 문서 식별자와 § 포인터로만 위임한다. 단계 전이가 어떤 전이 이벤트로 남는가(필드 구성·순서 보장·회수 이력 기록 방식)는 그 문서가 유지한다.
- **경계.** 전이 기록의 **물리 직렬화·저장 위치·물리 경로**는 본 문서가 서술하지 않는다 — Adapter Binding 문서 소관이다(03 §4.1 루프 상태 기록 직렬화 행·§4.2 이식 교체 지점 SP-3). 본 절은 단계 전이가 기록으로 남아야 한다는 **의무**만 명시하고, 그 기록 단위의 포맷과 물리 실현은 위 두 소관에 위임한다.

## §5. 경계·비의존 (재정의 0 · 인스턴스화 대상 경계 · 금지 토큰 · Glossary · 07 R2)

본 문서가 준수하는 경계를 한자리에 모은다. 검증 대조 지점이다.

- **03 계약 재정의·확장 0.** §2~§4의 모든 단계 전이 규칙·게이트-단계 매핑·전이 기록 의무는 03 §3.1-A/§3.2-A의 인스턴스이며 § 포인터로만 참조한다. 7단계 규칙 셀(§2.1)과 게이트-단계 매핑 표(§2.2)는 03 정본 문면을 그대로 보존한다(자구 왜곡 0, 03 내부 § 포인터는 "03 §…" 접두 관례로만 명료화, 새 규칙·새 전이·새 게이트·새 단계 0). 위반(03 Frozen 계약을 바꾸어야만 성립하는 경우)이 발견되면 구현하지 않고 Advisor에게 보고한다(structure.md §7 C-1).
- **인스턴스화 대상 경계.** 본 문서의 인스턴스화 대상은 03 §3.1-A 단계 전이 규칙(7단계 + 게이트-단계 매핑)이다. 재작업 루프(03 §3.1-B)·종료 규칙(03 §3.1-C)·사람 개입 지점(03 §3.1-D)의 상세는 재서술하지 않고 03 정본 § 포인터로만 참조한다(§0). 다만 각 단계의 실패 분기가 이들 § 포인터로 연결됨은 §2.1이 03 문면 그대로 서술한다(재작업 루프·에스컬레이션의 되돌림 대상·재시도 한도·종료 유형·사람 승인 조건 등 상세는 그 §가 소유).
- **사이클 구동 연산 경계.** 사이클 구동 연산(03 §3.1 입출력·재작업 루프 구동·종료·에스컬레이션)의 상세는 그 인스턴스 문서 소관이다. 본 문서는 그 소관을 침범하지 않고 일반 포인터(03 §3.1)로만 구분한다.
- **06 INV-9 경계.** CP2 판정의 기준·방법·내용은 06 소관이며 본 문서는 정의·재서술하지 않는다(§3). 시점·전이·시퀀싱만 본 문서가 배열한다.
- **07 R2 경계.** 같은 Wave에서 동시 작성 중인 형제 산출물의 미완성 내용은 인용·추측하지 않는다. 확정된 정본(03·02·06·structure.md·Glossary)과 형제 확정본(framework/loop/loop-state-record.md), 관례 표본(framework/verifier/verifier-protocol.md)만 참조한다.
- **금지 토큰 비의존(structure.md §5 C-3 확장, 03 INV-9) — 자가 전수 스캔 수행.** 본문 전체를 다음 후보 부류 **전체**로 전수 스캔하여 실증 0건임을 확인했다(단일 토큰 검색에 국한하지 않고 부류별 전수 대조) — { 특정 AI 이름·모델명·제품 기능명 } ∪ { 프로그래밍 언어명·툴체인명 } ∪ { 직렬화 형식명·확장자 } ∪ { 물리 경로·특정 Adapter Binding 문서명 }. 물리 실현·직렬화가 필요한 자리(전이 기록의 물리 저장 등)에는 구체 토큰 대신 "Adapter Binding 문서 소관"(03 §4.1) 포인터로만 대체했다 — 금지 토큰의 예시조차 본문에 나열하지 않았다(mention/use 경계). 다음은 금지 토큰이 아니다: (i) Lifecycle 단계 명칭(Consult/Plan/Execute/Verify/Learn/Memory Update/Complete)과 역할 명칭(Advisor/Planner/Worker/Verifier/human) — Glossary·AGENT.md 정본 어휘; (ii) 게이트·전이 열거 값 및 명명 라벨(CP1~CP3, PASS/pass/fail/escalated, INV·O·VT 라벨) — 03·02·06 정본의 평이한 열거 값·명명 규칙; (iii) 저장소 문서 식별자(`specs/…`·`framework/…`·`docs/…` 상호 참조 및 본 문서 자신의 식별자 `framework/loop/stage-transition-rules.md`) — 문서 식별자이며 직렬화 형식·물리 경로 토큰이 아니다(verifier-protocol.md §8·loop-state-record.md §7 분류 선례 동형).
- **Glossary 정본.** 사용 용어는 전부 specs/00-glossary.md §3.2-J(J-03: 단계 전이·루프 상태 기록·재작업 루프) 정본이거나 Glossary·AGENT.md 기존 어휘(Agent Lifecycle 단계·역할·검증·판정)다. 새 용어를 신설하지 않았다. "게이트-단계 매핑·검증 게이트·체크포인트(CP1~CP3)"는 03 §3.1-A 정본이 정의한 서술 명칭이며 본 문서 신설 용어가 아니다.

## §6. 요약 (규격 한눈에 보기)

- **단계 전이 규칙(§2.1)** — 7단계(Consult/Plan/Execute/Verify/Learn/Memory Update/Complete) 각각의 진입 조건·활동·완료 조건·전이·실패 분기를 03 §3.1-A 정본 셀 단위로 보존(자구 왜곡 0). 성공 경로 선형 순서(03 INV-1), 각 단계 실패 분기는 재작업 루프(03 §3.1-B)·에스컬레이션(03 §3.1-C/§3.1-D)의 § 포인터로 연결.
