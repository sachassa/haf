### §3.3 05 INV-4 · append-only(04 INV-6·INV-7) 준수 서술

- **05 INV-4 (승격 권한 Advisor 전속)**: 이번 승격 1건(L-15 → mi-0058)은 Advisor 승인으로만 성립했다. Active 레코드 mi-0058은 승격 성립 근거인 **Advisor 승인 기록 참조를 content(`approval`)에 자기완결 첨부**한다(§3.2 실측). Candidate 등록(mi-0057·mi-0059) 및 재발 판정(mi-0060·mi-0061)은 승격이 아니므로 승인 참조 대상이 아니다. 본 문서(Worker 집행)는 승격을 결정하지 않았다 — Advisor 결정의 물리 집행만 수행했다.
- **append-only (04 INV-6·INV-7)**: 이번 세션은 기존 레코드를 변경하지 않고 mi-0057~0061 **5건만 append**했다. status 전이(L-15 Candidate → Active)는 기존 항목 수정이 아니라 **새 레코드로 표현**됐다 — mi-0057(Candidate) 무변경 + mi-0058(Active, supersedes mi-0057) 추가. store 파일 쓰기 + index line append를 함께 완료했다(INV-7 정합 갱신).
- **기존 56건 무변경 실측(바이트 수준)**: 착수 시 mi-0001~mi-0056 56 store 파일 + index.jsonl의 **MD5 스냅샷을 사전 취득**했고, 등록 후 재계산해 대조 — 56 store 파일 MD5 **전건 불변**, index.jsonl은 append-only이므로 **기존 56라인 = 앞 17,044바이트가 사전 스냅샷 MD5와 완전 동일**(프리픽스 해시 5298A33BBE307798BFF764E696AA4246 일치), 신규 1,577바이트(5라인)만 append(총 17,044 → 18,621바이트). 즉 기존 56건은 store·index 양쪽에서 바이트 무변경이다.
  - **실측 범위 명시(06 §3.1 V4)**: 위 "무변경"은 **사전 스냅샷 대비 MD5 바이트 수준 대조**(store 56파일 개별 해시 + index 프리픽스 해시)에 근거한다 — 이 세션 착수 시점 스냅샷을 기준선으로 한 바이트 불변이며, 좁은 대리 지표(카운트만) 하나로 결론하지 않았다. index는 append 대상이라 파일 mtime이 갱신되나 기존 라인 바이트는 프리픽스 해시로 불변 증명했다.
