> 이 문서는 사용자 지시를 **소실 방지를 위해 축자(verbatim) 영속화**한 것이다. 지난 세션에서 이 태스크가 파일로 저장되지 않아 통째로 유실되었으므로, 착수 전 최우선으로 기록한다. 이 문서 자체는 신규 문서이며 기존 UAHF 정본을 수정하지 않는다.

## 목적

이번 작업은 **폴더 정리가 아니다.**

UAF의 장기 Architecture(v1.3 이후 포함)를 기준으로, Repository를 **앞으로 다시 변경하지 않는 것**을 목표로 Repository Architecture를 재구성한다.

이번 작업에서는:
- **코드 수정 금지**
- **Runtime 수정 금지**
- **기존 UAHF 수정 금지**

Repository Structure와 Markdown 이동 및 문서 구조만 변경한다.

## 중요 원칙

1. Repository는 **Layer 중심 구조**로 변경한다.
2. 각 Layer는 **독립적으로 사용**할 수 있어야 한다.
3. 각 Layer는 **독립적인 `.claude`**를 가진다. 최상위 `.claude`는 Global Default. Layer 하위 `.claude`는 Override만 수행.
4. 각 Layer는 자신의 **README**를 가진다.
5. 각 Layer는 자신의 **ARCHITECTURE**를 가진다.
6. ROADMAP는 **Layer별 Roadmap**를 가진다.
7. Root README는 전체 Framework 소개.
8. Root ARCHITECTURE는 **Layer 관계와 전체 구조만** 설명.
9. Root ROADMAP는 Framework 전체 Roadmap.
10. **Knowledge는 Layer가 아니다.** 모든 Layer가 Consult하는 공용 Knowledge Base.
11. **UAHF는 Runtime Layer의 구현체**다. Repository의 최상위 프로젝트가 아니다.
12. 기존 UAHF Source는 수정하지 않는다. **Directory만 이동**한다.
13. 기존 Entry / Discovery도 구현은 수정하지 않는다. **Directory와 문서 구조만** 변경한다.

## 최종 Repository (사용자 제안안)

```
Universal-Agentic-Framework/
├── .claude/                       # Global Default
│
├── entry/                         # .claude/ README ARCHITECTURE ROADMAP docs/ specs/
├── discovery/                     # .claude/ README ARCHITECTURE ROADMAP docs/ specs/
├── planning/                      # .claude/ README ARCHITECTURE ROADMAP docs/ specs/ contracts/
│
├── runtime/                       # .claude/ README ARCHITECTURE ROADMAP
│   ├── uahf/                       # .claude/ README ARCHITECTURE ROADMAP framework/ docs/ specs/ design/ templates/ tests/ memory/ lessons/
│   └── external/
│
├── knowledge/                     # .claude/ README ARCHITECTURE ROADMAP markdown/ metadata/ graph/ graphrag/ retrieval/ prompts/ patterns/ glossary/
│
├── docs/  design/  research/  templates/  tests/
├── README.md  ARCHITECTURE.md  ROADMAP.md
```

## 문서 수정 (Repository 변경 후 전건)

README · ARCHITECTURE · ROADMAP · Session Handoff · Verification Report · Promotion Review · 모든 Markdown 링크 · 상대경로 · 이미지 링크 · Appendix 참조 · Specs 참조.
→ **Repository 이동으로 인해 깨지는 링크가 없어야 한다.**

## Planner (Opus) 선행 산출물

Planner(Opus)가 Repository를 **실제 분석**하여 다음을 먼저 제출한다:
1. Migration Table
2. Repository Tree
3. 이동 대상
4. 문서 수정 대상
5. 위험 요소
6. Architecture 검토

→ Advisor는 **Architecture 관점 검토** 후 최종 Repository 구조를 **사용자 승인안**으로 제출한다.

**대안 의무**: Repository를 분석한 결과 더 나은 구조가 있다면 **반드시 대안을 함께 제시**하고, 현재 제안과 비교하여 장단점을 설명한 뒤 최종안을 추천한다.

이번 작업에서는 코드를 수정하지 않는다. Repository Structure · Directory 이동 · Markdown 이동 · 문서 링크 수정만 수행한다.
