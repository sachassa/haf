## §0. 이 문서의 위치·정본 경계

- 설치 **계약**의 정본은 specs/12-scaffold.md §3이다. 설치의 **물리 실현**(경로·직렬화·검사 도구·템플릿) 정본은 framework/adapters/claude/scaffold-binding.md다. 이 가이드는 그 둘을 신규 프로젝트 설치 **절차**로 엮은 사용자 안내다.
- 하네스는 현재 Bootstrap 상태다. 설치 3연산(Install/VerifyInstall/Uninstall)은 형태 A 문서 절차로 실현된다(scaffold-binding.md DP-U1). 무인 설치 실행기(형태 B)는 미도입이므로, 이 가이드는 **각 단계에서 무엇을 배치·확인하는가**를 서술하고 특정 실행 도구의 무인 자동화를 전제하지 않는다.
- 이 가이드는 후속 시연 산출물의 구체 내용을 추측하지 않는다 — 절차만 서술한다.

## §1. 목적·전제

이 가이드는 신규(또는 기존) 프로젝트에 UAHF를 설치하고, 설치 직후 Runtime Bootstrap이 성공하며 루프가 1 사이클 동작함을 확인하는 절차를 안내한다(ROADMAP v0.9 완료 조건 "설치 → 루프 동작").

**전제.**

- 설치 원본 = `framework/adapters/claude/scaffold-template/`(프로젝트 템플릿 물리 자산, scaffold-binding.md §6).
- 설치 대상 = 빈 프로젝트 또는 기존 프로젝트.
- spec 기준선 = v0.1(Frozen, 15건 — numbered 00~13 + TEMPLATE).
- Framework 버전 = v0.9.

**설치가 성립시켜야 하는 것(최소 구성 집합 — 13 §3.2-A 5요소).** 설치 직후 다음 5요소가 모두 성립해야 한다: 상위 규약 문서 · Agent 역할 정의 4종 · 위임·완료/실패 보고 프로토콜 · 검증 게이트(구현 주체와 검증 주체 분리) · 작업 추적. 이 성립이 Bootstrap 성공과 루프 구동의 전제다.

## §2. 설치 절차 (Install → VerifyInstall → Bootstrap → Loop 1 사이클)

### §2.1 Step 1 — Install (설치·부트스트랩)

입력을 정한다 (12 §3.1 Install).

- `target` — 대상 프로젝트(빈/기존).
- `moduleSelection` — **최소 필수 집합을 반드시 포함**한다. 최소 집합 = Runtime Bootstrap 필수 계약 + 최소 구성 집합(13 §3.2-A). 예: `runtime`(호스팅)·`agent`(역할 4종)·`verifier`(검증 게이트). 선택 Module(loop·memory·workflow·plugins 등)은 필요에 따라 추가한다(Modular — 필요한 모듈만, 12 INV-2). 최소 집합 미달이면 설치가 `ModuleSelectionInvalid`로 거부된다.
- `options` — 기존 파일 처리 정책(기본 = 보존).

배치한다 (scaffold-binding.md §3.1·§6).

1. 입력 접근성·`moduleSelection` 검사. 대상이 쓰기 가능한지, 최소 집합을 포함하는지 확인한다. 미달·불가 시 배치하지 않고 거부한다.
2. 기존 파일 처리. 충돌하는 기존 사용자 파일은 **보존**하고 `preservedPaths`에 기록한다(강제 옵션 없으면 덮어쓰지 않음, INV-3).
3. Project Template 배치. scaffold-template/ 자산을 대상 경로로 배치한다.
   - `dot-claude/AGENT.md`·`dot-claude/CLAUDE.md` → `.claude/AGENT.md`·`.claude/CLAUDE.md`
   - `dot-claude/agents/{advisor,planner,worker,verifier}.md` → `.claude/agents/*.md`
   - `dot-claude/settings.json.example` → `.claude/settings.json`(Project scope Config)
   - `framework/{core,runtime,adapters}/README.md` → 동명 경계(자리)
   - `specs/README.md` → `specs/` 생성 후 spec 기준선(v0.1, 15건) 배치
   - `install-manifest.template.md` → 값 채워 대상 매니페스트 파일
   - 주: `dot-claude/`는 설치 시 `.claude/`로 이름이 바뀐다(scaffold-binding.md §6.2). Global scope Config는 사용자·환경 전역 설정 소관이므로 Scaffold가 덮어쓰지 않는다. Module scope Config는 초기화 대상이 아니다.
4. Install Manifest 생성. `frameworkVersion`=`"v0.9"`·`specVersion`=`"v0.1"`·`installedModules`·`installedArtifacts`·`preservedPaths`를 기록한다(scaffold-binding.md §4, INV-7).

Install 완료 조건은 Step 3(Bootstrap Ready/Degraded)과 Step 2(체크리스트 전 항목 통과)이다. 하나라도 미충족이면 설치는 무효다(`BootstrapWouldFail`, INV-1).

### §2.2 Step 2 — VerifyInstall (설치 자가 검증, CK-1~CK-8)

설치된 구조 + Install Manifest를 대상으로 체크리스트 8항목을 실행한다 (12 §3.2-C, 검사 도구 = scaffold-binding.md §5).

| 항목 | 확인 내용 | 검사 방법 (scaffold-binding.md §5) |
|---|---|---|
| CK-1 | Project Template 필수 6요소 존재 | 파일 조회 — 설치 대상 경로 실재 |
| CK-2 | `moduleSelection`이 Bootstrap 필수 최소 집합 포함 | Manifest `installedModules` ↔ 13 §3.2-A 대조 |
| CK-3 | Config Global·Project 초기화 + 01 §3.2-B 스키마 일치 | Project scope 소스·Global 기본값 대조 |
| CK-4 | 설치 직후 Bootstrap `Ready`/`Degraded` | Bootstrap 재현 + `state` 관측(Step 3) |
| CK-5 | Bootstrap 이후 Loop 1 사이클 구동 | 핵심 루프 재현 + 통과 관측(Step 4) |
| CK-6 | 설치된 Core 디렉터리 AI 의존 0건 | 텍스트 검색 — `framework/core/`·`framework/runtime/` 전수 스캔 |
| CK-7 | Install Manifest 존재 + `frameworkVersion`·`specVersion` 표기 | 파일 조회 — 매니페스트 + 두 버전 필드 |
| CK-8 | 기존 사용자 파일 보존 (`preservedPaths` 일치) | 파일 조회 — 보존 대조 + 재설치 diff 0 |

전 항목 통과 시 VerifyInstall 완료. 산출물 누락이면 `IncompleteInstall`(location = 실패 CK 항목).

### §2.3 Step 3 — Runtime Bootstrap (Ready 확인)

설치 직후 Runtime Bootstrap(01 §3.1-C)을 세션/턴에서 수행한다(scaffold-binding.md §2 행 9, runtime-binding.md §3.4 — 세션 개시 = Bootstrap 구간).

- 필수 계약이 모두 해소되면 `state = Ready`.
- 선택 계약만 일부 누락되면 `state = Degraded`(Ready에 준함, 계속 진행 가능 — 01 INV-2).
- 필수 계약 미해소면 `state = Failed`(설치 무효 — `BootstrapWouldFail`).

`Ready`(또는 `Degraded`) 확인이 CK-4 통과다.

### §2.4 Step 4 — Loop 1 사이클 구동 확인

Bootstrap 이후 Loop Engine이 핵심 루프(위임 → 구현 → 검증 → 승인)를 최소 1 사이클 구동함을 확인한다(scaffold-binding.md §2 행 10, loop 구동 계약은 03 소관).

- 위임(Advisor) → 구현(Worker) → 독립 검증(Verifier CP2) → 최종 승인(Advisor CP3)의 사이클이 1회 통과한다.
- 구현 주체(Worker)와 검증 주체(Verifier/Advisor)가 분리되어, 구현자가 자신의 산출물을 최종 승인하지 못함을 확인한다(검증 게이트, 13 §3.2-A).

1 사이클 통과가 CK-5 통과이자 ROADMAP v0.9 완료 조건 "루프 동작"의 확인이다. (구체 사이클 재현 결과는 시연 Task 소관 — 이 가이드는 절차만 서술한다.)

## §3. 기존 프로젝트에 설치 (기존 파일 보호 · 멱등성)

기존 프로젝트에 설치할 때:

- **기존 파일 보호(INV-3).** Scaffold는 사용자 소유 기존 파일을 덮어쓰지 않는다. 충돌 파일은 보존하고 `preservedPaths`에 기록한다. 강제 덮어쓰기는 명시적 `options`를 요구한다(강제 시 `ConflictWithExisting` 경고). 누락된 UAHF 구성 요소만 추가 설치한다.
- **멱등성(INV-4).** 동일 입력으로 Install을 재실행하면 결과 구조는 동일하다. 이미 존재하는 Scaffold 산출물은 재생성하지 않고, 사용자 수정본을 덮어쓰지 않는다. 재실행 전후 구조 diff = 0(CK-8 재설치 diff 0).

---

## §4. 제거 (Uninstall — 제거 안전)

제거할 때 (12 §3.1 Uninstall, scaffold-binding.md §3.3):

- Install Manifest의 `installedArtifacts`만 제거한다.
- `preservedPaths`(사용자 소유 기존 파일)는 **보존**한다(INV-5).
- 제거 후 남은 항목(Manifest 소유이나 제거되지 않은 것)이 있으면 잔여 경로를 보고한다(`UninstallResidue`).

## §5. 실패 시 (Failure Report)

모든 연산의 실패는 공통 Failure Report(12 §3.2-D)로 보고한다 — `operation`·`target`·`reason`·`location`.

| 상황 | reason | 조치 |
|---|---|---|
| 대상에 쓸 수 없음 | `TargetNotWritable` | 대상 경로 권한 확인 후 재시도 |
| `moduleSelection` 최소 집합 미달 | `ModuleSelectionInvalid` | 최소 집합(runtime·agent·verifier 등) 포함해 재입력 |
| 기존 파일 충돌 (강제 시) | `ConflictWithExisting` | 보존 정책 재확인 / 강제 여부 재결정 |
| 설치 산출물 누락 | `IncompleteInstall` | location(실패 CK 항목)의 산출물 재배치 |
| Bootstrap 필수 계약 미충족 | `BootstrapWouldFail` | 최소 구성 집합(13 §3.2-A) 성립 여부 점검 |
| 제거 후 잔여물 | `UninstallResidue` | location(잔여 경로) 수동 정리 |

## §7. 요약 체크리스트

설치가 완료(ROADMAP v0.9 "설치 → 루프 동작")되려면:

1. Install — `moduleSelection` 최소 집합 포함, Project Template 배치, Install Manifest 생성(`frameworkVersion`·`specVersion` 표기).
2. VerifyInstall — CK-1~CK-8 전 항목 통과.
3. Runtime Bootstrap — `state = Ready`(또는 `Degraded`).
4. Loop — 핵심 루프 1 사이클 통과(구현/검증 주체 분리 확인).
5. 기존 프로젝트 — 기존 파일 보존(`preservedPaths`)·멱등성(diff 0).
6. 제거 — `installedArtifacts`만 제거, `preservedPaths` 보존, 잔여물 보고.
