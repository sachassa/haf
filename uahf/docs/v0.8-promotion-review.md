## §2. 판정

> 아래 §2.1~§2.5는 Advisor 확정 심사 판정(2026-07-06)의 문서화다. 판정 자체는 Advisor 전속 소관(05 INV-4·02 §3.2-A)이며, 본 문서는 재평가·변경하지 않는다.

### §2.1 L-14 — Active 승격 승인 (Advisor, 2026-07-06)

- **stable_id**: L-14. **요지**: Agent 기동 설정 파일(.claude/agents/ 이하 역할 정의 등)의 개정은 Worker 위임 권한만으로는 권한 시스템에 차단될 수 있다 — 승인 근거가 위임 메시지가 아니라 사용자 본인의 지시여야 하는 부류다. 이런 개정은 사용자 직접 지시를 근거로 주 세션(Advisor)이 직접 수행하거나, 착수 전 권한 경로(사용자 승인·권한 규칙)를 확보한 뒤 위임한다.
- **유래**: EX-R3에서 verifier.md 개정이 권한 시스템 [Self-Modification] 거부로 차단(planner.md는 통과 — 판정 편차 관측). Worker가 우회 부작위·실패 보고(blocking) 반환, Advisor가 사용자 직접 지시 근거로 직접 수정 완결.
- **승격 근거**: 실무 발생 사례이므로 즉시 승격 — 시연 픽스처가 아니라 세션 실무 사이클에서 실제로 발생한 차단이며, 재발 방지 가치·적용 조건이 명확하다.
- **승격 권한**: Advisor 전속(05 INV-4). Worker 자기 점검·Verifier 독립 판정은 승격 근거이지 승격 결정이 아니다.
- **물리**: Candidate 등록 mi-0052 → Active 승격 mi-0054(supersedes mi-0052).
- **승인 참조 content 자기완결**: mi-0054 content의 `approval` = "Advisor 승격 승인 2026-07-06 — docs/v0.8-promotion-review.md §1 (05 INV-4, 승인 참조 자기완결)". 승격 성립 근거(Advisor 승인)를 레코드 자체로 확인·검증할 수 있다(lessons.md §3.2 승격 레코드 관례 — 새 필수 필드 아님, 05 §3.2-A 필수 필드 전건 보존). 착수 시 실측으로 `approval` 필드 존재를 확인했다(§3).

### §3.2 실측 대조 결과 (직접 측정)

- **store·index 규모**: store **56파일**(mi-0001~0056) · index **56라인** — 직접 실측(파일 수·행 수 카운트).

### §3.3 05 INV-4 · append-only(04 INV-6) 준수 서술

- **05 INV-4 (승격 권한 Advisor 전속)**: 이번 승격 2건(L-14 → mi-0054, BPD-06 → mi-0056)은 모두 Advisor 승인으로만 성립했다. 두 Active 레코드는 승격 성립 근거인 **Advisor 승인 기록 참조를 content(`approval`)에 자기완결 첨부**한다(§3.2 실측). Candidate 등록(mi-0052·mi-0055) 및 재발 판정(mi-0053)은 승격이 아니므로 승인 참조 대상이 아니다.
- **append-only (04 INV-6)**: 이번 세션은 기존 레코드를 변경하지 않고 mi-0052~0056 **5건만 append**했다. status 전이(Candidate → Active)는 기존 항목을 수정하지 않고 **새 레코드로 표현**됐다 — L-14는 mi-0052(Candidate) 무변경 + mi-0054(Active, supersedes mi-0052) 추가, BPD-06은 v0.7 mi-0043(Candidate) 무변경 + mi-0056(Active, supersedes mi-0043) 추가. 같은 stable_id 중 최신 timestamp 항목이 현재 status를 해소한다(lessons.md §5.2).
- **기존 51건 무변경 실측**: mi-0001~mi-0051이 모두 유일·연속 id로 존재하고(재번호·누락 0), 51 → 56 증가분이 오직 append(mi-0052~0056)임을 실측했다. 추가로 v0.7 기준선 꼬리 mi-0045~mi-0047의 kind·stable_id/verdict·status·timestamp가 docs/v0.7-promotion-review.md §3 기록과 **동일**함을 대조 확인했다(append-only 보존 실증 — mi-0045 L-13 Candidate 22:20:31.602, mi-0046 recurrence Recurrence(L-08) 22:20:32.602, mi-0047 L-13 Active 22:20:33.602).
  - **실측 범위의 정직한 명시(06 §3.1 V4)**: 위 "무변경"은 **구조적 append-only 실측**(id 연속·재번호 없음·증가분만 append·v0.7 꼬리 timestamp·status 보존)에 근거한다. 이 memory-data 디렉터리는 버전 관리 하에 있지 않아 **사전 스냅샷 대비 byte 수준 불변 대조는 이번 읽기 전용 실측의 범위 밖**이다. 좁은 대리 지표 하나로 넓은 결론을 내지 않기 위해 이 경계를 명시한다.
