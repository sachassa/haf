## §0. 이 문서의 위치와 정본 경계

이 절이 본 문서의 경계 선언 정본이다(다른 절에서 반복하지 않는다).

- **정본은 specs/03-loop.md §3.1-A다.** 이 문서는 그 단계 전이 규칙(7단계 + 게이트-단계 매핑)의 **인스턴스**이며 재정의·확장하지 않는다. 계약 요소는 § 포인터로만 참조한다(structure.md §7 C-1). 위반(03 Frozen 계약을 바꾸어야만 성립하는 경우)이 발견되면 구현하지 않고 Advisor에게 보고한다.
- **Module 구현 디렉터리 문서.** `framework/loop/`는 structure.md §2가 지정한 경계다. 본문 전체에 금지 토큰(AI 이름·모델명·제품 기능명·언어명·툴체인명·직렬화 형식명·물리 경로·확장자)을 두지 않는다 — 규칙·분류 정본은 structure.md §5 C-3(및 03 §3.3 INV-9)이다. 작성 시점의 동시 작성 형제 불인용(07 R2)·추측 0(07 R4) 준수 서술 = 종전 문면 git 앵커 90ca19c(정본 = uahf/specs/07-workflow.md §3.2-C).
- **인스턴스화 대상 경계.** 대상은 03 §3.1-A뿐이다. 재작업 루프(03 §3.1-B)·종료 규칙(03 §3.1-C)·사람 개입 지점(03 §3.1-D)과 사이클 구동 연산(03 §3.1)의 상세는 대상이 아니며 § 포인터로만 참조한다. 각 단계의 실패 분기가 이들 §로 연결됨은 03 정본이 서술한다.
- **Verify 판정 내용 비정의(06 INV-9).** 본 문서는 Verify의 시점·전이·시퀀싱만 배열하고, CP2 판정의 기준·방법·내용은 정의하지 않는다 — 06 소관(§3).
- **전이 기록 포맷 비정의.** 전이 이벤트의 필드·스키마·append-only 불변의 포맷 정본은 03 §3.2-A와 형제 확정본 framework/loop/loop-state-record.md가 소유한다(§4). 물리 직렬화·저장 위치는 Adapter Binding 소관이다(03 §4.1·§4.2 SP-3).
- 용어는 specs/00-glossary.md §3.2-J(J-03) 정본만 사용한다. 새 용어를 신설하지 않는다 — "게이트-단계 매핑·검증 게이트·체크포인트(CP1~CP3)"는 03 §3.1-A 정본의 서술 명칭이다.

## §2. 단계 전이 규칙 인스턴스

### §2.1 7단계 진입·활동·완료·전이·실패

정본 = `uahf/specs/03-loop.md §3.1-A`(재정의 0 · 문면은 정본 참조). 7단계 성공 경로는 Consult → Plan → Execute → Verify → Learn → Memory Update → Complete의 선형 순서다(03 INV-1). 각 단계는 진입 조건 충족 시에만 진입하고 완료 조건 충족 시에만 전이하며, 모든 전이는 루프 상태 기록(03 §3.2-A)에 남는다(03 INV-3). 각 단계의 실패는 재작업 루프(03 §3.1-B) 또는 에스컬레이션(03 §3.1-C·§3.1-D)으로 분기한다.

인스턴스 고유 델타는 없다 — 진입/활동/완료/전이/실패 각 셀의 문면과 단계별 항목 표기 차이(Verify의 별도 "경계" 줄, Memory Update의 성공·실패 경로 분기, Complete의 완료 조건 내 실패 분기)는 03 §3.1-A 정본이 유지한다.

### §2.2 게이트-단계 매핑 (정본: 03 §3.1-A "게이트-단계 매핑")

Loop는 세 체크포인트의 순서를 불변으로 소유한다. 각 체크포인트는 다음 단계에 배치된다.

| 체크포인트 | 배치 단계 | 소유(내용) |
|---|---|---|
| CP1 Worker 자체 점검 | Execute 종료 → Verify 입력 | 02 (Worker) |
| CP2 Verifier 독립 판정 | Verify | 06 (Verifier) |
| CP3 Advisor 승인 | Complete 진입 게이트 | 02 (Advisor 최종 승인) |

"Verify 통과"는 CP2 PASS로 정의된다. 완료 보고는 Verify 통과 후에만 생성되며(02 INV-4·03 INV-2), CP2 PASS 전 완료 보고는 무효다. 이 배치는 02 §3.1과 정렬하고, 정합 확인은 03 §9 결정 기록("게이트-단계 매핑 승인")에 확정되어 있다.

## §3. 06 INV-9 정합 — Verify 시점·전이 소유 ↔ CP2 판정 내용 소관 (양방향)

06 INV-9는 "Verify 단계의 시점·전이·시퀀싱은 정의하지 않는다 (03-loop 소관). Verifier는 판정 기준·검증 리포트·독립성 계약만 소유한다"고 규정한다. 본 문서는 이 경계를 양방향으로 명시한다.

- **방향 1 — 시점·전이·시퀀싱은 03(과 본 문서 인스턴스)이 소유한다.** Verify의 진입 조건·전이 대상·게이트 시퀀스(CP1 → CP2 → CP3 불변 순서)는 03 §3.1-A가 소유하고 본 문서가 배열한다(§2.1·§2.2). 06은 이를 정의하지 않는다.
- **방향 2 — CP2 판정의 기준·방법·내용은 06이 소관한다.** 판정 기준 카탈로그·검증 리포트·독립성·거짓 완료 보고 검출은 06 §3.1·§3.2·§3.3 INV-1~INV-10 소관이며, 본 문서는 정의·재서술하지 않고 § 포인터로만 참조한다.

이 경계는 06 §9-OQ-V1과 06 §9 결정 기록(정합 확인 완료)에 정합한다. 순서(03) ↔ 판정 내용(06)의 분리는 순환이 아니라 위임이다.

## §4. 전이 기록 의무 (정본: 03 §3.2-A·INV-3; 포맷: framework/loop/loop-state-record.md)

- **의무.** 모든 단계 전이는 루프 상태 기록에 append-only로 남는다. 기록되지 않은 전이는 없다(03 INV-3). 성공 경로 선형 전이와 실패 분기가 유발하는 재작업 되돌림(03 §3.1-B)·에스컬레이션 전이가 모두 기록 대상이다. 전이는 기록된 뒤에 유효하며, 이 기록만으로 사이클 전체를 재구성·검증할 수 있어야 한다(03 §3.2-A·§7).
- **포맷 비재정의.** 전이 이벤트의 필드·스키마·단계 상태·append-only 불변의 포맷은 03 §3.2-A와 framework/loop/loop-state-record.md가 소유한다. 본 절은 의무만 명시하고 포맷과 물리 실현(Adapter Binding 소관 — 03 §4.1·§4.2 SP-3)은 위임한다.
