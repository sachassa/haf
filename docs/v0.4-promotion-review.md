## §1. 심사 기준 (05 §3.2-A 승격 3조건 — 재정의 없이 적용)

1. `failure`·`cause`·`lesson`·`applicability`·`provenance`가 모두 채워질 수 있다 (검증 가능성, 05 INV-5).
2. Verifier의 Learn 입력(독립 판정)이 실패의 실재를 뒷받침한다 — 이 초기 실데이터의 경우, 각 세션의 **실검출·재작업·교정 기록**(handoff §1.4류, v0.3 검증 리포트)이 그 근거다.
3. Advisor가 승격을 승인한다 — **본 문서의 각 판정이 그 승인이다.**

시연(M7)에서의 성립 방식: Register Candidate(여부=예 취급 — v0.4 계획에서 사용자 승인으로 전건 정식 기록 대상 확정) → 본 문서 §2 해당 행 참조 첨부 → Active 승격. 본 문서 참조 없는 승격 시도는 NotApproved다 (시연 ⓒ 음성 케이스).

### L-01 [승인] 상태 서술 전수 대조 (v0.1)
- failure: 기준선(Frozen) 확정 직후 Glossary 표에서 실제 상태와 다른 낡은 표기 2건("미작성")이 발견되어 즉시 교정이 필요했다.
- cause: 기준선 확정 전 최종 검증에 "문서 내 상태 서술 ↔ 실제 상태의 전수 대조" 절차가 없었다.
- lesson: 문서를 Frozen/기준선으로 확정하기 전 최종 검증에 상태 서술 전수 대조를 포함한다.
- applicability: 문서를 Frozen 또는 기준선으로 확정하려는 상황.
- provenance: task_ref=v0.1 Frozen 전이 / report_ref=docs/session-handoff-v0.1.md §5.3 항목 4 / origin_role=제출 Advisor(v0.1)·승인 Advisor(v0.4) / ordering_ref=v0.1 세션 (2026-07-05, v0.4 이전).

### L-05 [승인] 부수 산출 전수 보고 (v0.3)

### L-07 [승인] 상태 서술 실측 후 기록 (v0.3)
- failure: 산출물(A5 runtime-binding)이 실재하지 않는 파일을 "소스 실재"로 서술했다 — 게이트 C 파일 시스템 전수 대조가 검출했다 (v0.1 유형 재발).

- applicability: 산출물에 파일·자원의 실재 여부를 서술하는 상황.
- provenance: task_ref=v0.3 A5 / report_ref=docs/session-handoff-v0.3.md §1.4-1·§1.5-3 / origin_role=검출 Advisor(v0.3)·승인 Advisor(v0.4) / ordering_ref=v0.3 세션.
- 조건 2 근거: v0.3 §1.4-1 CP2 Fail→재작업 기록.

### L-08 [승인] 위임 done 문구 정밀도 (v0.3)

- provenance: task_ref=v0.3 A1 / report_ref=docs/session-handoff-v0.3.md §1.3(A1 재량 수용 후 표준화)·§1.5-4 / origin_role=검출 Advisor(v0.3)·승인 Advisor(v0.4) / ordering_ref=v0.3 세션.
