## §0. 이 문서의 위치·정본 경계·오케스트레이션 사실

### §0.1 위치·정본 경계

- **이 문서는 수행 기록이다.** 시연 1사이클을 실제로 어떻게 수행했고 무엇이 관측됐는가를 픽스처 실물 인용으로 기록한다. **독립 판정**(검증 리포트 CP2)은 이미 시연 내부에서 수행됐고, **본 시연 산출물 전체에 대한 최종 판정·승인**은 마일스톤 게이트(Advisor 게이트 C·CP2)가 담당한다. 상태 라인이 "CP2 대기"인 이유다.
- **판정 문장 인용(재정의 0).** 본 시연이 실증하는 C3의 판정 문장은 11 §3.1 C3 원문을 그대로 인용한다:

  > **C3 핵심 루프 통과** — 위임 → 구현 → 검증 → 승인 핵심 루프가 이 Adapter 위에서 1회 이상 통과한다 (ROADMAP v0.2·v1.0). (specs/11-adapters.md §3.1)

  본 문서는 이 판정 기준을 **재정의·확장하지 않으며**, C3 실증 근거(§4)만 산출한다. 등급 정의·Conformance verdict·Report 필드·최소 바인딩 부분집합 지위는 전부 11 §3이 소유한다.
- **Conformance verdict 미산출(선취 금지).** 본 문서는 **Valid(Minimal) 등 Conformance 판정(verdict)을 내지 않는다.** C1~C3 종합 대조·Conformance Report(11 §3.2-D) 산출·최종 등급 판정은 **후속 Conformance Task·마일스톤 CP2 소관**이다. 본 문서는 C3 loop_pass 근거(후속 Task가 인용할 형태, §4)만 제공한다.
- **소유 경계(07 R4).** 본 작업의 소유 경계 = 2산출물 — `docs/v1.0-generic-adapter-demo.md`(이 파일)·`docs/v1.0-generic-demo-fixtures/` 이하 전건. 라이브 표면(`.claude/`·`framework/core/`·`framework/runtime/`·`specs/`)·`framework/adapters/generic/`·claude loop-data·memory-data·형제 Task 산출물은 **수정하지 않았다**(§6 전수 대조). generic-binding.md는 읽기 전용 소비.

### §0.2 오케스트레이션 사실 (요약 — 상세 §5)

- 시연 사이클의 4전이 actor는 **역할명**(Advisor/Worker/Verifier)이다. 물리 수행 주체(주 세션 Advisor·T4 Worker[구현 대행]·독립 Verifier 실행 주체)의 명명·구분은 §5(투명 기재 절)에 둔다(DP-V5·DP-V6 — 명명은 본 문서 §5에 한정).
- **실위임(모의 아님).** 검증 단계는 **독립 Verifier 실행 주체에 실위임**했다 — 구현을 수행한 주체와 검증 주체가 분리되어, 구현자가 자신의 산출물을 최종 판정하지 못함을 실증한다(H-INV-2·13 §3.2-A 검증 게이트). 그 최종 응답이 검증 리포트(`reports/verification-report.md`)의 근거다.
- **actor=human 0건.** 사이클 기록 4전이 전건 actor ∈ {Advisor, Worker, Verifier}, human 0건(§5.3 실측).

## §2. 시연 설계 — 절차 (기대)

Advisor 확정 골격(위임 input·시연 설계)이다. 각 단계는 픽스처 실물로 남고 사이클 기록에 append된다.

1. **픽스처 구축** — `docs/v1.0-generic-demo-fixtures/` 아래에 generic 바인딩 값 실물 배치: 역할 정의 4종(BP-7, 실행 주체=임의 실행 주체 BP-9)·상위 규약+오케스트레이터 진입점(BP-8, 충돌 시 사람 보고 규칙 BP-14)·Config 소스(BP-3, 전역/프로젝트 + 역할 정의 내 설정 블록)·Module Manifest(BP-1, 머리말 메타데이터 블록+본문)·위임/보고 채널(BP-10·11)·사이클 기록(BP-13).
2. **핵심 루프 1사이클 실수행** — 4단계:
   - **위임**: Advisor 제공 8필드 위임 문면을 위임 메시지 파일에 기입.
   - **구현**: 역할 정의 로드(BP-2) → artifact 생성 → 완료 보고 파일(02 §3.2-C) 기입.
   - **검증**: 독립 Verifier(DP-E8)에 실위임 → done 3항목 독립 판정 → 검증 리포트 파일 산출. 구현/검증 주체 분리(H-INV-2). (물리 주체·모델 지정 §5.)
   - **승인**: 검증 리포트 `final_verdict = Pass`인 경우에만 Advisor 조건부 사전 승인 문면을 승인 기록 파일에 기입. Fail이면 승인 없이 실패 보고 반환.
3. **시연 문서 작성** — 이 문서(절차[기대] + 수행 기록[실측] 구분 절).

**시연 내 위임 문면(Advisor 제공 — 8필드, 임의 변경 금지):** { from: Advisor / to: Worker / task: 핵심 루프 4단계 요약 노트 artifact 1건 작성 / input: 상위 규약·역할 정의(픽스처 내) / output: 픽스처 내 artifact 파일 1개 / done: (1) 4단계 각 1문장 이상 (2) 위임 필수 필드 7종 열거 (3) 파일 1개만 생성 / context: 픽스처 상위 규약·역할 정의 / constraints: 픽스처 밖 무접촉 }.

**조건부 사전 승인 문면(Advisor 제공):** "핵심 루프 사이클 승인 — 검증 Pass 확인, Advisor (조건부 사전 승인 문면, 위임 시 제공. 최종 게이트는 본 시연 전체에 대한 Advisor 게이트 C·CP2가 수행)".
